# 与 AF 主体框架 Skill 协同

当同一仓库同时有 `animusforge-maintainer` 与 `.agents/skills/af-core-framework/SKILL.md` 时使用本说明。它澄清两套规则的职责，不是新架构、项目计划或额外操作授权；宿主/仓库更高层约束和最新用户请求仍需遵守。

本仓库采用用户选定主源的维护规则 0.2.0；主源位置及同步责任由根 AGENTS 记录。共享参考逐文件同步，本文件与仓库入口适配保留，不另复制一套架构、验证或台账规则。

## 谁管什么

| 工作 | 主用规则 | 边界 |
| --- | --- | --- |
| 普通功能、Bug、UI、配置、资源、兼容、性能 | 维护 Skill 的对应 workflow | 当前用户授权和真实 owner 决定范围；不自动改成全仓重构 |
| AF 主体、内部制作组接口、独立子 MOD API | 同时读取 `af-core-framework` | 当前仓库采用同 DLL 三层边界；不借通用 Skill 扩大制作组业务范围 |
| 仓库清理、职责拆分、原计划审计 | 维护 Skill 的风险对应表/工作包/复核方法 | HOLD/延期不算完成；前置条件只阻塞其实际影响的工作 |
| Skill 本身的更新 | 两者仅涉及的规则/引用 | 不要求搭建 ModuleHost、新增 manifest、运行游戏构建或安装全局 |

## 统一解释，避免假冲突

- **分层与程序集**：`AF.Foundation.Runtime`、`AF.Module.*`、`AF.Contracts`、`AF.Bridge.*` 描述逻辑职责/可选目标，不要求把本仓库的 `AnimusForge.dll` 拆成多份。Foundation 是平台安全与基础设施；对话、Prompt、动作、记忆仍由主体领域 owner 负责。不能把命名或目标清单写成已实现。
- **内部与外部**：supported/public capability 是跨 owner 的受支持契约，不强制 C# `public`。同 DLL 的制作组接缝可用 typed `internal`；独立子 MOD 才走单独版本化 public API。薄 adapter 只转接原行为，不自动升级为含新玩法/存档的共管 Bridge。
- **稳定与可改**：稳定分层/兼容承诺不等于冻结玩法、算法、提示词或功能上限。批准的主体变化应写明旧/新行为并更新相关测试；未经批准的其他语义保持。API 已开放能力以实际实现及当前交接为准，可以在需求与完整验证具备后演进，不能偷换 NotSupported。
- **运行现状与目标**：一套源码分别构建 1.3/1.4，两实现同名、Bootstrap 唯一加载、单模块发布是现状。通用 Host、manifest、profile、SafeMode 和独立 DLL 的未实现部分是另外的目标，不是普通类抽取的前置要求。
- **门禁适用面**：正式新模块/新跨域 Bridge 满足真实 owner、实际生命周期与组合验证；运行声明只在有消费者时按其 schema 提供。普通抽取不制造 manifest 或持久化命名空间，不等待无关清理；未实现目标诚实留待后续。
- **当前状态**：按最新请求、实际 Git/工作树与明确替代关系确定唯一当前状态入口，再读取对应 ledger。首选旧文件名不表示旧状态永远优先。只读审查不改台账；Skill-only 工作仅更新受影响说明/当前交接，不另起全项目重构台账。
- **代码交接**：主台账/代码范围图集中记录核实的一基行号、路径、符号、源码版本、真实调用者/owner 与未覆盖责任，HANDOFF 链接摘要。源码变更后更新定位与行为证据，不以刷新 hash 冒充修复。
- **实际性能**：每帧最多 N 个回调不等于最多 N 个 job/record；同时检查单回调内部批量和耗时。当前未解决的预算问题不能因 Skill 增加了规则就标为已修复。

## 安装与作用域

先用 Git 定位实际仓库，按根 AGENTS/HANDOFF 找选定 Skill 源；其他电脑的盘符、ZIP 原目录和全局宿主目录都不是写入目标。可由项目 AGENTS 明确读取维护 Skill，再按任务加载主体框架 Skill；不要求复制整套通用规则到第二个 Skill 目录。

若把维护 Skill 单独带到其他仓库，先确认是否存在对应框架 Skill；没有则按当前仓库的已批准架构执行，不臆造缺失接口或隐式安装另一个 Skill。只有用户要求全局安装才使用相应安装流程；本地文件修改不证明已有会话或另一宿主已经重新发现它。
