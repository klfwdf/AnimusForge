# AF 重构复核方法

用于明确的重构审查或原计划对照，不是普通开发的全仓审计门槛。

## 对照顺序

1. 核实请求范围、当前修订与实际工作树，区分源码、旧产物和他人改动。
2. 对原要求分别标已实现、部分、延期/HOLD、移交和排除；后两者不是完成。
3. 沿生产 caller → adapter/provider → 状态 owner → 执行/提交/退出核验，检查旧入口残余责任。
4. 分开判断确认缺陷、已知未完成、已授权范围变化和文档过时，不把它们统称架构偏航。
5. 使用[风险验证](validation.md)，区分本次执行、历史记录和 NOT-RUN。代码地图、文本断言、fixture 和 PE 元数据各有局限。

## 关键审查面

- Foundation 是否错误吞入领域策略；internal 契约是否被无理由 public 化；薄转接是否冒充 Bridge。
- 算法/状态是否真迁移，是否接通实际消费者，是否制造第二套执行/事实来源。
- 生命周期与故障隔离是否来自真实资源处理，而不只是目录状态；只对本任务承诺的能力判完成。
- 异步捕获、同代输入变化、代际/取消和真实 tick 工作量是否验证。
- 双版本、程序集/存档身份、三渠道及玩家数据是否保持；未验证部分是否如实标注。
- 当前状态是否唯一，已授权局部工作是否被无关 HOLD 阻塞，原未完成目标是否被误勾 DONE。

只读审查不实施修复、不切分支、不修改 runner 或安装依赖制造通过。浅克隆/稀疏检出的环境缺失要单列。
