## 1. 提取范围与明确排除

**提取：**

1. MSBuild 实际 `Compile` 输入：分别评估 `BannerlordApi=1.3/1.4`，加上 Bootstrap。
2. C# 普通、逐字、raw、插值字符串和字符常量；注释与未激活条件编译正文另行标记。
3. `content/content-map.json` 映射的文本资源、项目嵌入资源及模块/扩展的次级加载资源。
4. JSON 键/值、XML 属性/文本、其他映射文本文件；保留已存在的英文。
5. 原文、源文件/行列、上下文、占位符、去重原文与全部引用；补充原始汉字行清单，便于复核非字符串用途。

**世界书正文暂缓：**

- 精确排除 `knowledge/**` 和 `KnowledgeRules.json` 正文。
- 依据当前 `KnowledgeImportSupport.LoadKnowledgeRulesFromImportDir/TryLoadKnowledgeRulesFromRuleFiles` 实际消费者：`knowledge/rules/*.json`、`knowledge/single_rules/*.json`、`knowledge/*.json` 和合并的 `knowledge/KnowledgeRules.json`（源码第 52、97–99 行）。
- 排除清单只记文件路径、大小和 SHA-256，不复制正文到翻译清单。
- 世界书编辑器、导入/导出按钮、错误提示、加载器外壳和知识注入标题仍属于 MOD 英化范围。
- 不把名字含 `World` 的外交、公报、事件资源误当世界书；不一刀切跳过所有公开 `PlayerExports` 预设。

**不自动纳入产品翻译：** 原版反编译参考、测试/历史副本、私人运行时导出、个人配置/凭据、模型和第三方二进制。图片里的字需后续视觉盘点，本轮不声称已 OCR 全覆盖。

## 2. 分类原则

| 分类 | 后续处理 |
| --- | --- |
| 玩家界面/MCM/菜单/弹窗/通知/说明 | 第一优先级；优先复用已有 TextObject/语言 XML，不强改游戏语言 |
| 对话素材、规则、前处理/主链路/后处理、记忆/公报/外交/生图提示词 | 第二优先级；翻译自然语言，并核对要求输出中文/中文专用格式的约束 |
| 中文匹配、正则、替换、分隔符、字符判定 | 独立逻辑审查；补充英文输入或语言适配，而不是直接替换 |
| JSON 键、存档键、类型/枚举、资源 ID、动作标签、通道标识 | 默认冻结；必须证明非协议或提供兼容方案才能改 |
| 日志、异常、开发辅助界面 | 产品界面之后处理；日志结构与机器识别标记保持 |
| 注释、未激活代码、次级加载资源 | 只做覆盖与用途复核，不冒充玩家可见待译文本 |

自动分类只是分流提示，所有清单项初始状态均为 `review_required_not_translated`。相同原文在不同上下文不保证使用同一译文。

## 3. 实施批次

1. **基线与盘点**：创建分支、固定提取参数和文件哈希、验证排除范围、人工抽样。
2. **可见界面**：入口、MCM、通用通知、对话面板、信使、百科编辑器、公报/外交/政策/处刑/GCCZ 界面；统一术语表。
3. **提示词与素材**：三交流渠道共享规则同步英化；保留 tag、JSON 字段、占位符、解析期望及执行边界。
4. **中文依赖逻辑**：逐个追到实际消费者，分离展示字串与匹配语义；保持旧存档和中文自定义输入兼容。
5. **遗漏与发布验收**：检查已在英语覆盖范围内的中文残留、布局长度、英语模型响应和双版本构建；另行授权打包/部署。

GCCZ 如涉及可复用规则或集成契约修改，先在本工作区形成独立英文化资源/补丁说明；需要修改 `G:\AFMOD\GCCZ` 或其他融合树时，先获得该路径的明确授权，并遵守双边表示/同步规则。本轮只写提取工具和证据，不触发产品同步。

## 4. 每批验收门槛

- 原字符串的 `{变量}`、数字格式、TextObject ID、动作标签、转义及换行不丢失；英文排序不得改变协议语义。
- JSON/XML 可解析，语言文件真正被 `language_data.xml` 引用，映射与嵌入路径一致，非死资源。
- 改逻辑时复用现有最小专项；生产代码/兼容敏感变更验证两版构建及相关 Bootstrap 接缝，不更改官方一键流程。
- 三渠道提示词、动作后处理和事实/记忆语义保持一致；中文遗留必须有已审核的豁免用途。
- 最后以英语游戏语言检查可见文本与面板裁切；未实机时明确标记，不把静态提取或编译当成游戏验收。
- 世界书延期清单中的 SHA 保持；不静默替换用户自定义内容。
