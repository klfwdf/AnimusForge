# 制作组同步：AF 主体重构架构已确认

本次确定的是架构方向，不是宣布接口已经完成。

```text
AnimusForge.dll
├─ AF 主体：对话、LLM、Prompt、标签、记忆、调度
├─ 制作组内部模块接口/薄桥 → 政策、宴会、GCCZ 等
└─ 对外 API ← 独立子 MOD 的 DLL
```

- 制作组功能源码与 AF 一起编译进主 DLL，用内部代码接口协作。
- 子 MOD 是独立游戏 MOD/DLL，通过单独设计、版本化的公共 API 对接，不直接使用主体私有实现。
- 两类接口共享同一套主体管线，不再复制 LLM、标签、动作提交和记忆系统。
- 本任务负责 AF 主体与接口接缝；政策算法、宴会玩法、GCCZ 业务和各自存档不在此次重写范围。
- 模块自己定义业务规则并执行，主体协调请求、资格、调度及确认结果。NPC 答应或模块接受预约，不等于业务已经完成。
- 先整理内部边界和兼容桥，再确定外部 API 的稳定版本。当前不要求拆独立 Contracts DLL，也不改变单模块双游戏版本的加载方案。
- 旧 20 领域清单作为影响面/兼容检查参考，不再作为重写所有业务的任务清单。

制作组后续需要提供各模块现有接点、希望开放给子 MOD 的能力、状态/存档 owner 和行为验收用例；由对应作者决定模块业务的公共开放范围。

详细技术交接：[主体内外接口 HANDOFF](2026-09-09-af-core-internal-public-api-handoff.md)。本轮仅更新文档，未改生产代码、未推送或部署。已有修复测试通过不能替代这套新接口的后续兼容与实机验收。
