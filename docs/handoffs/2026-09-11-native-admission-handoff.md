# Native 对话准入修复：简明 HANDOFF

## 这次修了什么

- 发出对话前，先在主线程确定“跟谁说、哪次会话”，避免后台晚开始时换成另一个 NPC。
- 玩家输入与 NPC 主动开场共用后端忙碌保护，避免同时跑两轮；忙碌不会把对话框关掉。
- 读档、换场景或对话结束后，旧请求在动作前会被拒绝；旧请求结束也不能清掉新请求的忙碌状态。
- 旧界面的最后清理不再结束新会话的流式展示；准入失败保留输入或待开场状态。

## 保持不变

仍走原有完整 Native 对话流程；政策、宴会、GCCZ 业务没改。没有切默认渠道、没有开放新的公共提交 API，也没有推送或覆盖游戏。

## 检查范围

原代码问题有可复现的离线反例；当前有 44 项定向检查和 7 个变异控制。具体构建、回归、提交及未验证事项见总 `HANDOFF.md` 和本轮验证记录。**这些不是新版本的真实游戏验收。**
