# AF 初版框架交接（制作组简明版）

## 一句话结论

我们确定的“AF 主体 + 制作组内部接口 + 子 MOD 公共 API”架构，已经有第一版代码和实际接线了。**不是只画图，但也还不是整个重构全部完成。**

## 这次完成了什么

- 内部接口和外部 API 已分开，仍放在同一个 `AnimusForge.dll` 中。
- 政策、宴会、GCCZ 接入了 3 组内部接口，共 13 个方法、31 处调用。
- 原有模块业务没重写；原来的参数、规则、动作、事实和通知仍交给原负责人处理。
- 子 MOD 现在可以查询 AF 框架版本、装配状态和能力清单。
- 新增边界注释、架构说明、内部接入指南、公共 API 指南及回归测试。

## 现在暂时不能做什么

- 子 MOD 还不能通过新 API 直接提交对话、执行动作或修改记忆。这些能力会明确显示“未支持”，不假装已经做完。
- 不能把“接口已登记”当成“整个模块已验收”或“所有 NPC 都可以执行”。
- 不能直接删除仍有用途的旧入口，不能跳过新的游戏内测试就切默认。

## 接下来制作组怎么配合

1. 政策、宴会、GCCZ 负责人继续维护各自业务；需要 AF 对接时提方法/上下文/结果需求，不直接复制主体管线。
2. AF 主体下一步补 Native 请求排他与会话绑定、Courier 前置线程边界，再逐项开放公共提交/结果接口。
3. 集成测试重点看场景多人接力、旁听记忆、动作/事实是否重复、读档后晚返回是否串会话。
4. 独立子 MOD 作者先按新只读 API 做探测，暂不依赖 internal 类型或旧 ForExternal 兼容方法。

## 交付边界

本轮只改项目源码和文档、本地构建/测试与提交；**没有推送 GitHub、没有覆盖游戏、没有操作真实存档，也没有重启自动化**。
本轮生产/测试已本地提交 `a616958c`；Debug/Release 的 1.3、1.4、Bootstrap 共 6 项构建通过，相关离线回归通过。新接口的游戏内验收尚未进行。详细结果与下一步入口见根目录 `HANDOFF.md`。
