## 1. 最重要的结论

本任务重构的是 **AF 主体、制作组内部模块接口/薄桥，以及独立子 MOD 的对外 API**，不是重写政策、宴会、GCCZ 等全部功能业务。

制作组功能代码最终与 AF 一起编译进同一个 `AnimusForge.dll` 实现；子 MOD 是独立游戏 MOD/DLL，通过对外 API 对接。**内部代码接口与外部 MOD API 必须分开，但共享同一套主体管线。**

用户确认的目标如下：

```text
AnimusForge.dll 内部
│
├─ AF 主体
│    对话、LLM、Prompt、标签、记忆、调度
│
├─ 内部模块接口与桥接层
│    ├─ 政策模块
│    ├─ 宴会模块
│    └─ GCCZ 等制作组模块
│
└─ 对外 API 层
     ↑
独立子 MOD 的 DLL
```

这是逻辑分层，不是要求现在拆出大量 DLL。保留现有 Bootstrap 与单模块双实现输出：每次运行只加载对应游戏版本的一个 `AnimusForge.dll`；不是同时加载 1.3 和 1.4 两个实现。

当前约定不要求拆独立 Contracts DLL，也不授权把制作组模块改成独立 MOD。公共 API 的实现和必要公共类型可以先留在主程序集；若将来确有拆契约程序集的需要，另行论证类型身份、加载和旧子 MOD 兼容，不将其作为此次前置条件。

## 3. 我们做什么，不做什么

### 本任务负责

1. AF 主体的交互请求与渠道接入：原版对话、场景喊话，以及信使等渠道进入公共对话管线的接缝。
2. 公共 LLM 调用、Prompt 分阶段组装、标签协议、动作协调、历史/记忆/AFEF、必要展示/TTS 接线与生命周期。
3. 制作组内部模块的注册协议、上下文/规则贡献、动作调度、执行结果及薄桥。
4. 面向独立子 MOD 的受控、版本化公共 API 与文档/示例/兼容验证。
5. 迁移上述接缝时保留原功能和必要旧调用；清理已被证据证明替代的主体内部路径。

### 不在本任务中重构

- 政策效果算法、宴会流程/结算、GCCZ 玩法/规则/业务状态机。
- 这些模块自身的业务存档设计、数值、规则优先级和配置含义。
- 独立子 MOD 的内部实现；不能把独立子 MOD 偷偷编入 AF 来代替对外 API。
- 因为某项代码目前位于主 DLL，就将其全部认定为 AF 主体。
- 信使队伍寻路/运输等非对话玩法；原有赠予、关系等基础交互按功能基线保留，不借接口整理扩写其业务。

**允许整理的是接缝，不是业务。** 优先在主体侧薄桥调用模块既有入口。如果发现接入确实需要改模块内部，应列出最小需求与行为影响交对应 owner 协调，不凭“主体重构”自行扩权。

## 4. 制作组内部接口：同 DLL 内协作

内部接口服务于统一编译和发布的代码，可以采用 `internal` 接口、强类型调用和集中装配。没有必要为了同程序集调用再增加网络或到处使用反射。

建议内部协议覆盖六类职责，以下为设计分组，不是已经冻结的 API 签名：

| 分组 | 主体负责 | 模块/薄桥负责 |
|---|---|---|
| 注册与激活 | 确定顺序、能力和作用域，检查重复/缺失 | 声明模块 ID、依赖、支持渠道、激活条件 |
| 上下文与话题 | 组织捕获与规则选择阶段 | 在限定作用域贡献自身背景、候选和资格 |
| Prompt 贡献 | 保持前处理/正文/后处理顺序与预算 | 提供对应阶段的规则片段，不改整份全局 Prompt |
| 动作定义与调度 | 通用协议解析、路由、取消与提交守卫 | 定义动作参数、领域规范化、资格与执行处理器 |
| 执行回执 | 统一解释状态、协调历史/AFEF/通知 | 报告真实业务结果、确认事实与失败原因 |
| 生命周期 | 主线程调度、请求作用域、过期/清理 | 维护自身资源及业务状态，不接管其他模块 |

内部模块仍不得任意修改主体私有字段、可变存档字典或当前会话。需要活跃游戏对象的操作留在明确的主线程适配/执行阶段；后台处理只用冻结数据。

核心算法依赖内部接口，不依赖某个具体政策/宴会类。组合入口与薄桥可以知道具体模块以完成装配，这种有限依赖不应扩散回核心管线。

## 5. 子 MOD 对外 API：独立编译与发布

对外 API 是单独设计的公开面，不能简单把全部内部接口改成 `public`。

- 子 MOD 通过自己的游戏模块入口，在约定的 AF 就绪阶段获取版本/能力并接入。
- 仅开放明确支持的请求、查询、注册和通知，不提供任意内部方法执行器、任意反射入口或全部配置/密钥读取。
- 公共数据尽量使用稳定 ID、只读上下文、结构化参数与结果；不依赖主体 Behavior、UI VM 或裸可变内部容器。
- 外部请求进入同一主体规则/后处理/提交管线，不允许另开绕过资格和回执的快捷执行路径。
- 缺少模块或能力、版本不兼容、请求过期应有明确结果，不以静默成功代替降级。
- 通用对话子 MOD 可直接使用 AF API；扩展 GCCZ 的子 MOD 只使用 GCCZ owner 明确开放的能力，不因此获得所有 GCCZ 内部状态。
- 制作组模块若需自己的公共扩展面，由对应 owner 决定开放业务；我们提供统一接入机制，不替其设计全部玩法 SDK。
- 当前不建设 DLL 下载器、每帧插件扫描器或任意运行中热卸载机制。既有游戏模块加载方式保持。

内外接口复用同一主体服务和必要的数据语义，但开放范围、调用适配与兼容承诺不同。注册/能力限制属于合作式工程约束，不是隔离任意同进程 DLL 的安全沙箱。

## 6. 标签、动作与事实闭环

每个扩展动作应成套登记：稳定动作 ID、参数 schema、支持渠道/作用域、规则资格、后处理定义、规范化/验证处理器、执行处理器和回执语义。具体命名及签名待接口表评审，不在本文直接冻结。

```text
输入/上下文捕获
    → 话题与资格选择
    → 主 LLM 正文
    → 后处理动作提案
    → 协议解码＋模块权威归一化/资格校验
    → 形成经过授权的 ActionPlan
    → 主线程重新确认目标与请求有效性
    → 模块执行业务
    → 执行回执
    → 对应历史、AFEF 与通知
```

必须保持：

- 主体负责协议与协调；模块负责动作含义和业务执行，不能把宴会/GCCZ 规则重新藏进主体分支。
- 标签格式及输出要求进入后处理，不泄漏到普通 NPC 正文；可见文字清理与保留后处理证据的 raw 分开。
- 原始模型标签只是一份提案；不得跳过模块权威归一化，将 raw 直接交给可执行 ActionPlan 路径。
- 既有标签先由兼容映射/桥接承接，不要求模块立即全部改协议；未知、冲突、未启用或本轮未授权的动作不得执行。
- 所有者和命名空间明确，一个动作不能由两个处理器无约束地各执行一次；规则顺序确定，不能抢占式覆盖全局状态。
- 回执明确区分拒绝、接受/排队、已执行、部分执行和结果未知。预约宴会不等于宴会已发生；LLM 承诺不是确认事实。
- 延迟业务由原业务 owner 维护进度，在真实完成时再报告对应结果；不把其状态机迁入主体。
- 每步事实只有一个提交责任人。迁移期桥可以承接旧模块结果，但不得让旧模块和新主体重复写同一条历史/AFEF。
- 取消只保证阻止尚未开始或已过期工作；不承诺撤销已开始副作用。部分成功/未知结果不得盲目自动重试。

## 7. 稳定性、性能与兼容红线

1. 内部接口可在制作组协调下同步修改、统一编译；外部 API 的既有签名/类型身份/语义不原地破坏，新能力通过明确版本或可选能力增加。
2. API 版本、动作 payload schema、Prompt 版本、存档版本、游戏版本分开。不能仅凭一个程序集版本号代表全部兼容。
3. 不移动旧存档类型、改变 `SyncData` key、枚举值或序列化身份来完成接口拆分；模块私有数据保持各自 owner。模块缺失不应默默删除其存档数据。
4. 同源同名类型分散到不同程序集不自动二进制互通。现有 SceneActions 独立/融合构建差异必须核对；已有子 MOD 二进制兼容不能只靠源码重新编译证明。
5. 请求绑定 generation/session/epoch、目标及必要的输入序号；稳定人物 ID 不等于瞬时 AgentIndex。切场景/读档/替换目标后拒收旧回调。
6. 保留 Bootstrap 的双版本选择与必要类型预加载；不能为了“按需加载”破坏 Gauntlet/现有启动顺序。
7. 注册及能力检查集中进行并缓存；每轮只调用相关贡献者，限制数量/文本预算/耗时。不得每帧扫描全部模块、每轮注入全部规则或重复做同一网络前处理。
8. 保留有调用或存档/公开兼容责任的旧入口。仅删除已证明被替代的路径，不以 Legacy 名字或行数作为删除依据。
9. 模块失败应被适当隔离并给出诊断，但不能保证任意模块异常都无副作用；必要安全补丁不因可选模块开关而关闭。

## 9. 接口架构完成的验收标准

- 新增一个内部模块动作主要修改该模块的桥接注册/处理器，不再在 AF 对话大类中到处添加专用分支。
- 最小独立子 MOD 不反射 AF 私有方法即可完成一次受支持的对话/动作交互；同时保留或明确处理已有 API 消费者。
- 受控测试输入下，内部与外部两种接入共享同一生成、授权、提交和记忆语义；不是只检查接口能调用。
- 可选模块未激活、能力缺失、版本冲突、重复注册和处理器异常有明确结果；普通 AF 对话不依赖某个额外模块才能工作。不以此承诺任意中途卸载存档 owner 安全。
- 非法/未授权标签、目标替换、读档、取消、重复及迟到回调不能绕过主体执行守卫。
- 已排队/已执行/部分成功/未知结果与对应 AFEF 一致，不重复执行或虚报完成。
- 旧 API 兼容测试包含保留的旧客户端二进制；旧存档类型/键与代表性存档加载分别验证。
- 1.3/1.4 与 Bootstrap 构建、原相关回归、受影响模块桥接回归通过；实机、旧档和真实第三方单独记录。
- 记录冷启动和交互热路径开销，不以减少功能或消除资格检查换取速度。

构建/fixture 通过不等于公开 API 已稳定、全部子 MOD 兼容、零 BUG 或整个阶段八 DONE。
