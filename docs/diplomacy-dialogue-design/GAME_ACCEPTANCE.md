# 游戏内验收清单

本清单尚未执行。使用独立测试存档，分别检查支持的游戏版本；当前任务没有覆盖游戏模块。

1. 在信使、自由对话、场景喊话中分别劝国王议和。同意后有 NPC 正式提案，私下同意不立即停战；玩家自己正式接受后才停战。检查贡金、期限、割地与原话一致。
2. 保留一项无关外交事件，连续谈成和平、贸易等新事项。事件并存且独立推进；关闭其中一项不关闭其他项。存读档后归属、来源、条款仍一致。
3. 玩家没有国王身份，劝 B 国王接受 A 的和平提案。B 正式回应 A 的原案；玩家不是条约当事国。多份同类原案必须澄清，未获知、过期及改条件不能伪装接受。
4. 公开外交中核对作者记得最近玩家交谈与自身经历。私人理由和保密内容不进入公开公文；公文发布、实际获知及真实效果进入正确人物 AFEF。存读档／故障恢复不重复效果。
5. 分别提出吞并、朝贡、驻军、完全臣属，覆盖 AI—AI、玩家接收及玩家主动臣属。仅正式接受后执行，角色正确；检查领地、贡赋、自主权限、战争／和平同步与服从度规则。
6. 检查明确延期、恢复及取消的理由。主动延期在每日维护和存读档后保持；旧国王未公开承诺在更替后终止。已公开未接受提案通过正式宣言撤回，已生效协议不被私人谈话撤销。
7. 检查玩家国王明确口头宣战仍即时生效；普通玩家、威胁、假设和劝 NPC 宣战不能误触。NPC 宣战先发正式宣言；独立玩家家族停战保留原例外。
8. 在明确延期或发文技术失败期间修改未公开约定，准确引用旧 ID、版本和原因。新条件通过校验后旧版本失效；错误来源／版本不改变旧安排。存读档、晚到处理与每日恢复均不能发布旧条件。已经公开的提案先正式撤回后改案。
9. 分别核对三渠道约定的渠道、交涉来源与会话；场景排队后保留原来源，嵌套臣属／吞并适配不改成另一渠道，私下原话不进入公开公文。
10. 若记忆提交发生故障，检查原始事实、日期与人物称谓保留，跨日及读档恢复只补写记忆。多次延期／恢复和不同延期原因不产生同来源内容冲突；已发布而私人状态落后的故障按正式回执恢复，不重复发文或效果。

记录游戏版本、存档、渠道、来源公文／动作、回合、实际结果及日志。合同回放与真实效果验收分别保留证据。
