# 外交对话、个人记忆与宣言衔接方案

日期：2026-10-02。

本文将 Q1—Q16 已确认的玩法决定整理为完整功能方案，并给出工程边界与验收标准。2026-10-03 按用户“做完”“继续跑”的要求补齐运行链路和必要的独立事件支持；源码验证与游戏内验收的边界见 [实施记录](IMPLEMENTATION.md)。

## 目标与范围

统治者发布宣言时，应使用与当前议题相关的个人经历、与玩家的交往、私人承诺以及已知外交材料。玩家既可通过长期交往改变统治者的判断，也可通过一次明确交涉促成具体外交安排。

常规国家外交路径为：

> 玩家建议 → 统治者考虑、拒绝或接受 → 外交安排 → 正式公文 → 必要的正式回应 → 游戏动作 → 结果写入记忆。

一次覆盖现有国家口头外交，并新增吞并、朝贡、卫戍、附庸的完整宣言路径。支持合法的玩家—AI、AI—AI 国家组合，也支持玩家主动向 NPC 提出臣属。

保留两个即时例外：

- 玩家以有权身份亲自当场口头宣布宣战，仍可立即执行，无须系统替玩家发布宣言。
- 独立玩家家族与王国的停战沿用现有即时机制，不扩展家族公文外交。

玩家劝 NPC 国王接受未来宣战安排，走正式宣言路径。普通讨论、考虑和未经落实的口头承诺不能被登记成外交状态已经改变。

最初将多回合共存列为另一任务的依赖。后续完整交付要求下，本次在既有外交 owner 内补充本功能必需的独立事件存储、按 ID 推进与原案索引；更广泛的底层架构重建仍不属于本任务。见 ADR 0002 的后续实施决定。

## 已确认的玩法规则

| 规则 | 确定行为 |
| --- | --- |
| 劝说资格 | 任何能接触统治者的玩家均可尝试；接受程度受身份、信任、经历和国家利益影响。 |
| 国家权限 | 劝说资格不授予签约权，正式决定者必须有当前国家权限。 |
| 个人影响 | 相关私人经历、情感、恩怨和承诺可影响国家取舍。 |
| 明确承诺 | 原则上落实；重大局势变化或条件未满足可延期、修改或撤回，必须记录原因。 |
| 新事项 | 统治者明确接受后直接创建新外交回合，不等待正常周期。 |
| 回应原案 | 正式接受或拒绝进入具体原案所属回合。 |
| 新条件 | 另起新回合正式提出，旧原案不会被偷偷改写。 |
| 重复交涉 | 重复确认同一安排不会重复创建相同事件。 |
| 多案歧义 | NPC 先询问具体来源或条件，确定原案后再承诺及正式回应。 |
| 玩家发文 | 玩家宣言只能自己写、自己发；系统不能代写或代为正式接受。 |
| 玩家口头约定 | 对方 NPC 国王正式提出约定条件，等待玩家自行正式接受。 |
| 保密 | 私下交涉细节默认受保护；明确要求保密的信息不直接公开。 |
| 消息真实性 | 玩家转述保留来源与未证实性质，不能冒充系统确认事实。 |
| 更替 | 原统治者未公开的私人承诺终止，不由新任国王继承；历史记录仍保留。 |
| 国家历史 | 已发布提案和生效协议按国家外交规则处理，不能套用私人承诺终止规则。 |

## 回合归属与第三方斡旋

先判断本次交涉究竟是新事项、回应原案、不同条件、重复确认，还是仅讨论；不能只输出“议和成功”等笼统结果。

### 原案定位

当前源码的原案身份是 `SourceDocumentId + SourceActionId`，归属回合来自原案所在容器或源公文；没有可直接沿用的独立 OfferId。口头后处理应携带具体原案引用，代码校验并据此确定 RoundId。

候选原案来自有权回应国、准确提出国、外交种类、开放状态及人物可知范围。若交涉明确指定某份原案，精确绑定；若只有一份有效匹配，可绑定；若多份无法区分，NPC 追问。

归属优先级：

1. 仅讨论或考虑：记录交涉，不提交正式外交行动。
2. 重复确认已有安排：返回该安排当前状态，不重复创建。
3. 接受具体有效原案：提交正式回应，进入该原案所在回合。
4. 提出新事项或不同条件：立即请求建立独立新回合。
5. 原案歧义：先澄清，不猜最新或最早，不新建来逃避歧义。
6. 原案已过期、已答复或失效：说明原因；明确重开交涉后才可成为新事项。

玩家说“我接受”仍只构成口头交涉内容，不能代替玩家自己的正式接受公文。此路由分类必须同时检查实际决定者，不能把玩家的话直接转换成 AI 的正式回应。

### 具体场景

| 场景 | 正确归属 |
| --- | --- |
| A 向 B 提出和平，玩家劝 B 接受原案 | B 正式回应 A，进入该和平原案的回合。 |
| A 和 B 同时有贸易事件 | 贸易事件不因两国相同而被选中。 |
| A 对 B 有两份不同和平原案，玩家未说明是哪份 | B 询问来源、时间或条款，暂不回应。 |
| 玩家劝 B 向 C 提出一项新和平方案，已有 B—C 贸易回合 | 创建新的和平事件，只关联相关旧资料。 |
| 玩家是 A—B 交涉的第三方 | 玩家是斡旋者，正式作者仍是 B，正式对象仍是 A。 |
| 原案在模型回复期间失效 | 发布前拒绝失效回应，记录原因；不偷偷创建替代方案。 |

每次发布和执行均复查原案、实际权限、条款与世界状态。另一回合改变了战争关系时，旧提案不能盲目执行。多回合世界状态协调由底层实现，本功能要求它提供当前有效性判断和带回合身份的结果。

## 宣言与外交动作

| 功能 | 口头承诺后的路径 | 生效要求 |
| --- | --- | --- |
| NPC 宣战 | 新回合发布正式宣战公文 | 当前有权主体，动作合法；正式发布后执行。 |
| 和平 | 正式提出和平条件，或正式接受指定原案 | 双方正式同意相同原案，条件当前可兑现。 |
| 结盟、贸易 | 正式提案与指定原案回应 | 双方正式同意同一事项。 |
| 解盟、取消贸易 | 有权决定方发表正式解除公文 | 按既有单方解除规则执行，不要求对方同意。 |
| 国家吞并 | 正式吞并提案与接受 | 接收国与并入国明确，双方有权正式同意。 |
| 朝贡、卫戍、附庸 | 正式臣属提案与接受 | 宗主国、臣属国、类型和条件明确，双方有权正式同意。 |

和平、结盟与贸易沿用既有合法性和动作执行规则。单方解除不能用“两个国家 ID”推断是谁作出的决定，必须记录实际决定者。

吞并与臣属需新增正式意图、条款、原案、接受／拒绝与执行映射，直接手写的玩家宣言和 AI 自主宣言也应可以进入同一流程。不能只给口头外交增加一份结果公告，就声称这些功能已接入宣言。

条约角色不能从玩家身份推断：

- 吞并明确记录接收国和并入国。
- 臣属明确记录宗主国、臣属国及类型。
- 朝贡国继续沿用贡赋换保护、保留军事自主、不承担出兵义务的规则。
- 卫戍国继续沿用出兵、不交贡赋、没有军事自主权及现有忠诚度规则。
- 附庸国继续沿用贡赋、出兵及宗主控制外交军事的规则。
- MCM 功能开关、现有外交代表权与臣属限制继续校验。

扩展国家组合时，既有只面向玩家的执行入口必须泛化为按条约角色执行的入口，并保留既有政治、家族、领地、资金、军权和存档语义。玩家主动向 NPC 提出臣属时，玩家的国家表态仍由玩家亲自发布，AI 正式回应；不自动替玩家选择条约。

## 承诺与条款生命周期

外交安排至少记录：安排 ID、交涉来源、渠道、承诺者人物与所属王国、实际决定者、对象、动作、约定条件、允许公开的材料、来源原案、关联回合、状态与原因。

建议状态流：

> 明确接受 → 新事件已建立／原案正式回应已提交 → 公文生成中 → 已发布 → 等待必要回应 → 已执行。

延期、撤回、失败和原统治者更替是独立状态，保留原因。创建事件不表示正文已生成；发布公文不表示双方协议已生效。

私下约定的具体条款应固定为该安排的版本。正式公文不得凭生成模型自行增加赔款、割地、贡赋或军权义务。接受原案引用原案条款；修改条件须明确为不同方案，不能用接受原案的动作替换原案条件。

发文前双方明确修改安排时，使旧版本在途结果失效，并按新条件规则处理。已公开的公文保留原文和历史；后续撤回、拒绝或改案通过新的正式文书表达。修改公文不是回滚已经生效的战争或条约。

原统治者死亡或失去统治权时，尚未公开的私人安排终止，挂起的生成结果不可继续发布；即使事件已经创建，也要以明确原因结束该未发布安排。继任者可以按国家知识获得已公开历史，但不会接收前任的私人感情与未公开承诺。

## 记忆读写与隐私

### 宣言前读取

在生成开场、回应及相关后续公文时，为当前实际发文统治者读取：

- 人格与背景。
- 最近与玩家交涉的有效历史，包括尚未压缩材料。
- 与当前议题相关的压缩记忆及记忆总览。
- 恩怨、私人承诺和当前外交安排。
- 本人已发布、已正式收到或通过传播获知的外交公文与确认结果。

按议题、对象和相关事件检索，不只按字面“外交”关键词；救命之恩、亲属遭遇和欺骗记录也可能相关。材料来源与真实性分类必须保留，明确区分玩家陈述、NPC 表态、公开公文及系统确认结果。

原案尚未送达或未获知时，玩家口述不能直接证明正式原案存在且条款可靠；使用既有传播、展示或核验入口获取实际原案后才提交正式接受。

共享外交档案只承担相应公共历史。私人记忆按本次统治者身份提供为受限材料，不混入所有国家共享的档案或长期公共 prompt 前缀。正式输出只使用允许公开的内容。

### 交涉和执行后写入

继续使用 AF 同一套最近历史、每日草稿、压缩记忆和总览，三渠道共享读写：

- 玩家发言与 NPC 发言保留 user／assistant 语义。
- 明确承诺、安排创建、延期、撤回和失败各自记录真实阶段。
- 本人正式发文和正式收到提案作为公开外交行为事实记录，不能伪造一次面对面聊天。
- 已执行的外交结果在成功回执后写入 AFEF 确认事实。
- 受案方在实际收到或获知后才能读取相应材料；其他国家继续按传播范围获知。
- 不把单方发布的和平意愿写成战争已经结束，不把玩家口头同意写成玩家正式签约。

事实与记忆写入带来源 ID 去重。重试、读档和重复回调不能重复执行动作或重复堆积记忆；记忆提交失败保留可恢复回执，不能为修复记忆再次执行游戏动作。

## 三渠道与职责

自由对话、场景喊话、信使沿用同一前处理、正文规则、后处理授权、外交入口和记忆语义。信使在实际送达并完成 NPC 回复处理时形成交涉结果；不能在玩家发信时推定已获 NPC 接受。

正文让 NPC 自然表达考虑、拒绝、承诺和必要的原案澄清；动作标签只进入对应话题的后处理规则。后处理从本轮给定的合法对象和原案候选中输出具体安排或回应。资格、原案绑定和效果执行由代码校验。

逻辑职责建议如下，不代表当前源码已完成这些分层：

- AF 交互与记忆侧：提供共享交涉输入、个人记忆查询、历史和事实提交。
- 薄适配入口：映射身份、渠道和来源，转交命令并展示回执。
- 外交应用侧：拥有安排创建、原案路由、条款版本、取消／失效、正式公文提交和结果协调。
- 外交领域侧：拥有权限、条约角色、合法性、原案一致性与确定失败原因。
- 游戏适配侧：主线程解析实时对象、执行并回传效果；隔离 1.3／1.4 API 差异。
- 多回合底层：独立事件创建、跨活动回合提案查询、按 ID 推进、公文路由与世界状态协调。

不新增通用 LLM 客户端、私有聊天记忆库或渠道专属外交算法。通用记忆由 AF 持有，外交安排归外交状态所有，保持单一可写来源。

## 与多回合底层的合同

原 `ActiveRound` 为单值，`EnsureActiveRound` 会复用它。本次保留其正常周期职责，新增并存事件集合，并由同一 owner 实现如下合同：

| 能力 | 输入／输出与约束 |
| --- | --- |
| `QueryAnswerableProposals` | 按受案国、提出国、类型、状态和人物知识查候选；返回原案公文／动作、回合、条件与有效性。 |
| `StartNewRoundFromCommitment` | 输入稳定安排 ID、AI 发起人、对象、动作、条款版本与来源；立即创建独立事件并返回 ID，重复请求返回同一结果。 |
| `SubmitFormalResponseToProposal` | 输入确切原案身份、受案方、正式回应作者与安排版本；进入原案回合并准备正式回应。 |
| `CancelUnpublishedCommitmentWork` | 撤回、版本变更或统治者更替时，取消该安排尚未发布的工作，保留原因。 |
| `RevalidateAndReport` | 按回合、文书、动作和安排身份校验并回传发布、正式接受及游戏效果结果。 |

新事件不能复用、覆盖或关闭其他活动事件，也不能等其他事件结束才创建。原案回应不能仅按相同国家选回合。LLM 生成仍遵守通用调度预算，事件创建与正文完成各自可追踪。

上述必要能力已接入实际 owner，并通过双版本编译程序集的存档与索引回放。真实游戏传播及外交动作仍须独立验收，不能由合同回放代替。

## 持久化、失败与性能

工程上保留既有外交存档身份 `_af_world_diplomacy_v1`，增加兼容的可选安排及并存事件数据和必要索引恢复，不设第二套外交状态库。旧档缺字段时使用空集合与安全默认值；保存稳定 ID 和值，不保存实时 Hero／Kingdom／UI 对象。

后台请求使用不可变快照和安排／条款版本。回调在主线程重新校验发文人、原案和当前世界；失去权限、取消、重复和过期结果不能发布或触发效果。技术失败按既有有限修复与重试策略恢复，不能退回旧口头执行路径假装成功。

性能频率与策略：

| 路径 | 运行频率 | 策略 |
| --- | --- | --- |
| 个人外交材料 | 每次实际宣言生成请求 | 按人物、议题、对象和记忆修订号查询；复用不可变材料，限制输入预算。 |
| 原案候选 | 每次有关交涉请求 | 按受案国、类型、开放状态索引；按知晓范围过滤，限定返回预算。 |
| 安排去重 | 创建、确认、修订请求时 | 按交涉来源及安排身份查询；不得依靠全文相似度合并不同条件。 |
| 合法性复查 | 接受安排、发布前、效果前 | 获取有界实时快照，不逐帧扫全部王国或公文。 |
| 更替与失效 | 相关事件或底层有界维护时 | 按人物／王国和来源提案索引定向处理，不增加空转轮询。 |
| 事实／记忆提交 | 公文或效果回执时 | 来源去重、回执恢复、按既有预算分批处理。 |

缓存按人物记忆、外交知识、原案状态与安排版本失效；不同统治者的私人材料不能复用。候选截断不能把“没看到其他原案”误当作“只有一个原案”，应返回仍有歧义的状态。没有外交命中的普通聊天不额外扫描全局外交历史。

## 实现触点与边界

实施前必须重新核对实际工作区、分支、现有作者改动与源码位置。当前 E 盘调查不是切换其他工作树的授权；不推送、不覆盖游戏、不改一键构建流程。

候选触点：

- `WorldDiplomacyBehavior.cs` 的作者上下文、公文生成、原案绑定、正式动作入口和传播回执。
- `DiplomacyBehavior.cs` 的标签分派、权限校验及现有直接执行路径。
- `AnimusForge/ModuleData/RuleBehaviorPrompts.json` 的外交与臣属话题、后处理规则。
- `AnimusForge/CustomPrompts/WorldDiplomacyPrompt.json` 及代码中的正式意图／条款结构。
- `KingdomAnnexationBehavior.cs`、`VassalageBehavior.cs`、`NpcTributeVassalageBehavior.cs` 的国家组合与效果适配。
- `MyBehavior` 的共享记忆查询／提交入口和三渠道适配。

这些是责任位置，不要求把新编排堆入旧 Behavior。先建立真实统一入口与执行闭环，再逐项替换旧直接执行路径。一次交付覆盖全部已确认动作，可以使用多个经验证的本地实现切片；最终不能把未接入吞并或臣属的半成品称为完成。

兼容性实施遵循 `docs/bannerlord_1_3_to_1_4_5_compatibility_diff.md`，优先已有兼容帮助类，主线程游戏效果验证 1.3／1.4 两套实现。构建使用项目既有隔离验证方式，不改一键编译或部署脚本。离线回放与构建证据和 live-game 验收分别报告。

## 验收场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 国王记得玩家救命或欺骗经历 | 相关材料进入宣言决策，并与人物取舍连贯；未暴露保密交涉。 |
| 对话后仅说“会考虑” | 写入交涉，没有已接受安排或实际外交变化。 |
| 非国王玩家劝 NPC 宣战成功 | 新回合与正式宣言，发布前不提前开战。 |
| 玩家有权亲自当场口头宣战 | 保留即时效果，记录真实结果，不自动代写玩家宣言。 |
| 玩家国王口头谈妥和平 | NPC 正式提出原约定，等待玩家亲自正式接受；口头同意不触发和平。 |
| 第三方劝 B 接受 A 的原案 | 正式作者 B、对象 A、回合属于该原案；玩家不是协议方。 |
| 同国多议题／多原案 | 正确绑定具体原案；有歧义先追问，不选相关或最新回合。 |
| 重复确认与请求重试 | 同一安排、同一创建结果，不重复建事件或执行。 |
| 接受时修改条款 | 不冒充原案接受，新条件作为新方案处理。 |
| 旧国王在发文前死亡或退位 | 私人安排终止，晚到生成结果无效；新任不继承承诺。 |
| 另一个回合先改变世界状态 | 发布与执行时复查，旧失效条件不执行。 |
| AI—AI 吞并／三类臣属 | 双方有权正式同意，正确国家角色、既有效果和结果事实。 |
| 玩家向 NPC 提出臣属 | 玩家亲自正式发文，NPC 正式回应后成立，不自动为玩家选择。 |
| 独立家族停战 | 原机制保持，不误入国家公文或扩展范围。 |
| 自由对话、喊话与信使 | 同资格、同安排和原案规则、同效果入口与记忆语义。 |
| 保存／读档、取消与重复回调 | 恢复待处理状态，已完成效果不再次执行，记忆失败可恢复。 |

验收应包含纯规则和应用层假端口回放、必要旧档／恢复场景、真实三段式标签链路、1.3／1.4 构建及最后独立 live-game 场景。还要验证旧口头直接执行入口只保留两个已授权例外，其余国家动作真实进入统一宣言路径。
