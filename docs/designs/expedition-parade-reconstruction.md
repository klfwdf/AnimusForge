## 已落地的功能

1. **两种阅兵**：出征阅兵（当前仍在进行的战争，宣战后 0～14 天，向城外行进）、胜利阅兵（核实的优势和谈后 0～14 天，反向入城）。不把单场战斗胜利当战争胜利。
2. **场所与入口（已按新要求调整）**：大地图城镇／城堡菜单的“举行阅兵……”入口放在“处决”上方，进入后选择出征或胜利；没有处决项的城堡放在“离开”前。玩家拥有该据点，或玩家作为该阵营统治者；菜单直开不要求任命总督或总督在场。旧总督原生对话菜单已移除，AF 现场 AI 总督代办入口保留，通信／信使不触发现场阅兵。
3. **兵员来源**：主队伍、当地驻军、已集结的玩家率领军团。只读健康非英雄士兵；不转移、不征募、不扣兵，不改驻军编制。展示 Agent 使用独立 origin，清理只处理本次生成的 Agent／坐骑。
4. **队列与旗手**：步兵／弓兵三列；骑兵／骑射两列。每个有士兵的纵列第一人为旗手，按来源使用旗帜；全程固定列数，不临时挤成单列、不瞬移越门。
5. **自动描点与路线校验**：查找城门及集结锚点，结合导航网格生成路线；约每米采样，验证各列与外沿净空、局部路径不绕墙、城门两侧空间及穿门方向。缓存复用前重新验证。无有效路线就停止，不假装通过。
6. **行动控制**：菜单点击后立即调用入场流程，不依赖被暂停的大地图 Tick；AI 代办仍在结束交谈后准备。入场前复核地点、权限、14 天窗口与健康兵员，AI 请求额外复核原总督。队列跟不上会停等；持续卡住 25 秒则停止清理；离开场景、进入战斗或异常时清理。
7. **AF AI 对接**：新增中英文 `expedition_parade` 规则和实时可用条件。只允许后处理认可的单一类型；一次性短期执行凭据阻止原始对白直接触发。接受安排只表示待集结／待路线检查，不记录“阅兵已完成”。
8. **存档**：保存宣战快照与有效胜利窗口；不保存临时 Agent、等待中的请求或 AI 执行凭据。

## 首版明确采用的口径

- “优势结束战争”：有贡金时，以接收贡金的一方为优势方；零贡金时，必须有本功能记录的开战领地快照，按双方净领地变化之差判断。不确定或平局不开放胜利阅兵。
- 领地变化是阵营整体快照，不是逐座城堡归因到某一场战争；多线战争的归因仍需后续细化。
- 安装前已结束的战争不追溯伪造胜利记录。安装前已经开战但还在 14 天内的战争，可通过原版 `WarStartDate` 开放出征阅兵；无开战快照的零贡金和谈不会凭空判胜。
- 当前上限是总计展示 96 人，每个来源／兵种分组拆成最多 24 人一批；前一批全部通过后放下一批。所有非空来源尽量有代表，配额不超过真实健康人数。
- 这是首版性能边界，不是把整支军团永久拉入主队。暂未增加围观群众、撒花、音乐、奖励、独立镜头或手工路线编辑器。
- 不会自动打开／破坏城门，也不会绕过缺失的场景导航网格。无门锚点、城外没有可行区域的场景会明确拒绝；模组自定义场景可能需要适配。

```powershell
./scripts/build/check_expedition_parade.ps1

# 指定 SDK 和 AF 私有运行库，构建双版本、执行原有门禁并打包到本副本

  -SdkDirectory '<dotnet SDK directory>' `

  -BuildPackage
```

## 必须进行的实机验收（尚未执行）

先备份一份存档；只启用一个 AF 模块版本。不要覆盖主开发目录。每个场景测试从同一份战前存档重新开始：

1. 在己方城镇和城堡宣战，检查“举行阅兵……”位于处决项前；无处决项时在离开前。分别有／无总督测试菜单直开；第 0 天和第 14 天出征选项可用，超过 14 天置灰并提示原因。非授权据点、围城或俘虏状态不可触发；AI 代办仍拒绝非总督。
2. 分别用纯步兵、纯骑兵、混编；每列旗手可见；列数全程不变，转弯／过门不挤墙，不遗留马匹。记录场景名和日志中的 route samples。
3. 主队＋驻军＋已集结军团均有代表；受伤、英雄和未集结军团队伍不混入；开始、结束、Esc 离开、卡门停止后对比各队伍真实名册完全一致。
4. 从大地图城镇／城堡的阅兵子菜单、街道 AF 对话、原生 AF 对话分别发起；大地图暂停时点击也应立即进入场景，返回不应排队，离开阅兵场景后返回原城镇／城堡菜单，旧总督对话菜单项不再出现；一次只排一场。测试询问、拒绝、重复标签、双类型、无资格以及直接在玩家文本写 ACTION 标签，均不应造成错误开场。
5. 以收贡金／付贡金／中立平局／有准确领地快照的优势和谈分别结束战争，检查只有正确一方开放胜利窗口；存读档后窗口延续且不重置日期。
6. 无城门锚点、关闭城门、拥堵、窄转角、缺失城外导航区域：拒绝或安全停止，绝不能以穿墙／瞬移伪装成功。
