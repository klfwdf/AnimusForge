# 外交文书代拟方案

日期：2026-10-05。基于用户Q1—Q8明确回答整理；用户随后授权实施，本地产品22cbb228已完成并通过离线验证。同日后续授权已将全部既有外交改动部署至游戏，详见[交付说明与验证边界](../diplomacy-round-design/UPDATE_20261005.md)；仍未实机/真实provider验收。访谈与源码证据见 [design-discussion.md](design-discussion.md)，术语沿用 [外交术语表](../diplomacy-dialogue-design/CONTEXT.md)。

## 玩家流程

在现有纸面输入标题、提纲、简短诉求或已有正文 → 点击“书记官代笔” → 生成完成直接回填 → 玩家修改并自行发布。

新宣言和外交回应均提供按钮。只有现有正文栏，不增加独立标题、委托弹窗、预览页、版本列表或撤回按钮。回应原案所需内容由玩家写入提纲，不自动读取来文。

每次代笔都使用当前纸面文本并发起新请求。内容没有修改时，再点一次就是重新措辞；已有手写或AI正文也可再次整理。空白输入不请求AI，提示“请先写下标题或拟文要点。”

## 写作材料与边界

请求只包含当前纸面文本、现有外交MCM自定义偏好，以及简短固定代拟任务约束。正文不得擅自添加国家、人物、领地、金额、期限、既成事实或额外外交动作；保持玩家原意、立场和已给条款。条件缺失时不编造具体条款。

沿用外交自定义偏好中的文风，篇幅要求优先于“简明/简短”偏好；简明表示措辞精炼，不能压缩到要求篇幅以下。标题或简短提纲需扩写为完整外交公文，通过组织段落、阐明原有立场与诉求扩写，不添加实质条件。偏好中的利益判断或行动取向不能代替玩家作出新决定。写作指令可以体现在玩家提纲中，事实、数字和外交意图仍须保留。

不注入世界局势、长期外交档案、个人记忆、政策材料或收到的原文。不调用原有自主DECLARE任务，不生成actions、round_plan、声誉或游戏执行指令；结果只承载正文。

生成不建立外交回合、不公开公文、不写外交历史/记忆、不产生外交行动。玩家点击发布后继续原有发布、原案路由、传播及解析执行链路。

## 沿用现有设置

- 篇幅：直接使用“AI外交宣言最小字数”和“AI外交宣言最大字数”。沿用1—1000归一化、最大值不小于最小值、设置缺失默认100—500的语义（2026-10-06获准调整，保留用户已有自定义值）。生成前给出范围及其中点作为目标篇幅；生成完成不以该区间拒收或提示字数偏差（2026-10-11用户明确调整）。
- 文风：读取现有“AI外交与书记官代笔偏好”原值。该值与NPC外交使用同一来源，编辑它后，下次代笔读取新值；不增加代拟专用提示词文件或编辑器。
- 接口：复用外交现有接口、模型、Token及思考设置的配置解析与回退方式，即优先事件/叛乱API、配置不完整回退主API；不增加独立接口下拉或密钥配置。取消固定1800 Token请求上限，按本次最大篇幅×4＋256准备输出容量，给中文分词和JSON留余量；请求上限不是要求模型用尽的Token数量。仍服从玩家显式设置的API输出上限；截断时保留原文并提示检查API输出上限。

点击时在主线程对正文、当前设置、窗口身份与存档生命周期作快照；修改MCM设置影响下次请求，已发出的请求继续使用本次快照。

生成前按可见正文字符要求篇幅，标点计入，排版空白不用于凑字数。完整有效正文直接回填，不进行MCM区间计数、拒收或字数提示；玩家仍可自由编辑后发布。

输出为空、格式损坏、截断或超过既有编辑器6000字符技术容量时，保留原文并反馈失败；不靠截尾破坏条件，也不自动循环重试。不因正文偏离MCM目标篇幅要求玩家重新生成。

## 按钮与布局

底部顺序为“取消 ｜ 发布外交文书 ｜ 书记官代笔”。发布按钮的几何中心对准纸面中心；左右按钮以等宽占位及对称间距布置，避免用三按钮整体居中代替发布居中。

保留现有卷轴、印章和按钮样式。印章嵌在背景右下，优先将按钮行上移到印章上方并适当调整正文下边界；具体高度、宽度和间距结合真实背景验证，不照搬当前两按钮尺寸。三个按钮文字完整，处于同一水平线，互不重叠，整个按钮矩形与印章留有可见间距。

生成时按钮文案变为“书记官拟稿中…”，禁用代笔和发布；取消仍可用，正文仍可编辑。成功、失败、过期结果以现有轻量提示方式告知，不再加一组按钮。

## 异步与失败

- 同一窗口一次只运行一个代拟请求。后台只处理冻结文本、配置与网络；游戏对象读取和UI回写留在主线程。
- 完成时重验窗口/请求身份、存档generation、当前正文与请求正文。窗口关闭、重开、切换存档或当前文字发生变化时，旧结果不覆盖输入，也不能解除另一个新请求的忙碌状态。
- 失败保留原文，恢复按钮，并提示手动重试。代拟使用冻结配置的单次发送入口，不使用外交默认的两次失败重试；既有provider思考参数不兼容时的协议降级仍沿用，不新增重新生成或修稿循环。未解析的原始响应、代码围栏及内部输出字段不进入正文。
- 关闭窗口后不回填；释放窗口拥有的请求资源，并在现有传输支持的范围取消请求。不能将当前政策的“忽略回调”误认为已有网络取消能力。
- 正式发布继续使用原有资格判断；代拟不得打开新的发布资格或绕过现有条件。

## 最小实现范围与性能

修改现有外交ComposePopup的布局和VM；在外交模块内增加小型代拟输入/输出、任务构建、请求与回填处理。复用政策的交互模式和既有LLM传输能力，不迁移政策代码，不重构外交调度器，不新增公开API或独立模块/DLL。

固定代拟合同限定“忠实扩写/重新措辞，沿用本次长度与偏好，只输出正文”，放在共享原偏好之上。共同外交契约中涉及自主选择目标、动作和历史的内容不带入本次任务。输出可使用单一body字段的固定结构，协议字段属于内部实现，不新增用户配置。

只在点击时做一次输入快照、常数时间的篇幅预算计算和请求，回填时做一次有界文本清理；无Tick扫描国家或档案、反射枚举、空转轮询、长期记忆检索或多轮评议。不会因该帮写功能新增存档记录。

## 验收条件

1. 新宣言、回应均有代笔按钮；发布严格居中，三按钮对齐且不遮印章，目标游戏分辨率/UI缩放下文字完整并可点击。
2. 标题式、要点式和已有正文均可生成回填；重复点击按当前文本重写。空白输入不发送请求。
3. MCM长度设为不同区间，代拟读取并遵守对应范围；最大值小于最小值按既有语义处理。改变现有外交文风影响下次代拟，无新的配置入口。
4. 对已给国家/数字/期限/领地/立场的样例检查保留情况；对只写“议和”的样例检查不凭空新增赔款、割地、盟约等条款。任务合同和样例检查不能替代玩家发布前审阅，也不宣称代码能证明所有自然语言的外交语义完全一致。
5. 请求内容不含世界历史、来文或个人记忆，不生成外交动作；代拟后未发布时回合、公开档案和游戏关系保持原状。
6. 请求失败、空/坏格式/截断/超编辑器容量、生成期间编辑、关闭后重开、读档及旧请求晚到都不覆盖新输入；完整稿偏离MCM篇幅仍直接回填；不能重复发送或自动发布。
7. 实施后通过现有官方构建流程验证BannerlordApi=1.3、1.4及Bootstrap；用最小相关测试验证输出合同、长度和异步失效边界，并在游戏中验收布局/输入焦点。真实provider测试与实机结果分别记录，不用构建通过替代。
