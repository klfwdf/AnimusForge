## 0. 文档优先级与本轮总目标

本文取代并删除以下旧外交交接文档：

```text
docs/world_diplomacy_handoff_20260720.md
docs/world_diplomacy_handoff_20260804.md
```

下一阶段必须首先解决两个相互关联、但不能混为一谈的核心问题：

1. **外交事件缺少真正可能引发战争的矛盾。**
   当前 LLM 经常选择贸易、一般边境事务或温和交涉。即使文本看起来有争执，也常常没有领土、主权、复仇、战争责任、敌对政策、势力扩张等足以支撑战争升级的真实矛盾。
2. **已经出现的矛盾无法可靠地激化为实际冲突。**
   当前回合可以经历谴责、警告、拒绝和“最后通牒”，但最后通牒没有结构化要求、期限与违约后果，也不会在遭拒或逾期后进入一个必须处理后果的决策节点，因此经常以继续发文或回合自然关闭结束，而不是由 LLM 正式选择宣战。

这两个目标的职责边界必须保持清楚：

- 第一个问题解决“为什么会产生值得打仗的争端”；
- 第二个问题解决“争端已经严重时，为什么始终没有走到战争或可信的退让”；
- 不能仅靠提高一个数值阈值同时掩盖两个问题；
- 不能由 C# 越过 LLM，根据压力分数自动替国家宣战；
- 也不能重新建立固定话题池，把每场外交硬绑成贸易、边境或战争。

## 1. 当前外交系统的基本职责边界

当前正确方向仍然是：

```text
真实世界状态、国家战略、人物性格、外交历史
                    ↓
        LLM 自主选择议题、对象、立场和意图
                    ↓
       C# 校验身份、状态、对象和动作合法性
                    ↓
       宣言传播、各国按已知信息接力回应
                    ↓
   LLM 明确提出或接受正式外交行为，C# 执行
```

C# 应负责的硬限制包括：

- 王国与统治者身份有效；
- 被俘统治者不得代表国家发布新宣言；
- 国家拥有独立外交权，臣属关系和宗主代表正确；
- 参与国规模不超过 MCM 设置；
- 不得向自己宣战、与已经交战的国家重复宣战；
- 和平提案、同盟提案和贸易提案的接受或拒绝必须对应真实、仍开放且版本正确的来源提案；
- 玩家作为统治者时，AI 严禁冒用玩家身份作答或替玩家发布外交决定；
- 真正改变游戏状态的动作在执行前再次检查当前世界状态。

C# 不应负责：

- 根据关键词判断正文“像不像”某类外交；
- 要求正文必须出现“提议、建议、请求”等固定词；
- 用 `switch(topic)` 将话题绑定为唯一动作；
- 把非法或缺失的意图默认替换成贸易；
- 因回合即将结束而强行制造宣战、议和、结盟或贸易结果；
- 达到战争压力阈值后绕过 LLM 自动宣战。

外交正文、理由、语气、条件以及国家是否愿意采取某种合法行为，原则上交由 LLM 自主决定。代码只拦截会造成状态错误、身份错误、重复执行、玩家被代答或来源串线的问题。

## 2. 核心问题一：缺少战争矛盾

### 2.1 现象

- 和平时期的正常回合高度偏向贸易、商路和一般边境交涉；
- 边境问题经常只是“希望协商”，缺少不可兼容的领土或主权要求；
- 历史战争、真实战斗、领土易手、文化故土、敌对政策和统治者个人仇怨没有稳定转化成可供本回合判断的冲突材料；
- LLM 选择“安全且可继续对话”的题材比选择战争风险更容易；
- 只要求“每场都有外交目标”并不能保证会出现战争目标，贸易仍可能成为最容易合法成立的选项。

### 2.2 目标

让 LLM 在开场时能够看见足够真实、紧凑且彼此有差异的冲突机会，但仍由它依据国家战略、实力、关系、人物性格和近期历史自行决定是否利用这些矛盾。

建议为开场决策提供结构化的“局势依据”，而不是固定话题答案，例如：

- 当前或近期领土丢失、争议定居点、文化故土和历史统治权；
- 最近真实战斗、伤亡、俘虏、处决、袭掠和商队损失；
- 统治者及主要贵族的敌对关系、家族仇怨与声望损失；
- 接壤关系、边境兵力变化和军力优势；
- 对方扩张、结盟、臣属、政策与本国长期战略的冲突；
- 反复遭拒的真实旧提案、未兑现承诺和已经传播到本国王庭的宣言；
- 当前合法动作集合，例如宣战、解盟、断贸、提出结盟或继续交涉。

这些材料应当是“可引用的事实和机会”，不能变成：

```text
冲突分数超过 X → 必须宣战
话题属于边境 → 只能最后通牒或宣战
最近没有战争 → 程序强制生成战争题材
```

### 2.3 建议实现方向

1. 在新回合开场时构造一个限长、稳定排序的冲突机会摘要；只在开场生成一次，后续接力不重复全量扫描。
2. 将“是否存在值得升级的矛盾”与普通合作机会并列交给 LLM，而不是人为把战争放成默认答案。
3. 提示词明确要求：若国家存在领土、主权、复仇、安全或扩张方面的严重利益冲突，不要总是退回贸易；但仍允许认为开战不合算。
4. 保存本回合实际选择的矛盾依据和外交方向，后续发言只携带短摘要，避免每一轮重新选择议题或重建世界候选表。
5. 保留近期主题摘要，用提示词避免在没有新事实时原样重启同一议题；不要恢复固定主题冷却表，更不能因此把所有候选都推向贸易。

## 3. 核心问题二：矛盾不能激化为实际冲突

### 3.1 当前真实行为

当前真正能够立即触发战争的意图是：

```json
{
  "author_intent": {
    "intent": "declare_war",
    "commitment": "binding"
  }
}
```

在对象和状态合法时，代码才会调用游戏宣战机制。单纯在正文中谴责、威胁、警告或写“最后通牒”，均不等于宣战。

目前常见路径是：

```text
矛盾出现
  → 谴责或警告
  → 对方拒绝
  → 发布最后通牒
  → 对方再次拒绝或超时
  → 再次发文 / 回合关闭
```

其根因不是宣战执行入口完全不存在，而是“最后通牒之后必须重新面对后果”的决策链缺失。

### 3.2 战争压力现状

系统仍会记录战争压力，并将其作为定性历史提供给 LLM。最后通牒可能增加战争压力，但压力本身不会自动触发战争。

旧 MCM 字段：

```text
EnableWorldDiplomacyForcedWar
WorldDiplomacyWarPressureThreshold
WorldDiplomacyPeacePressureThreshold
```

目前属于废弃兼容字段，不应直接恢复为“达到阈值就强制宣战”。此外，需要检查最后通牒是否在文档压力和无机械结果压力两处被重复累计；如果确实重复，应统一成一个明确入口，避免同一份公文重复记账。

战争压力的合理用途是：

- 作为 LLM 看到的紧张程度与历史后果；
- 影响下一次是否继续忍让、升级或撤回；
- 用于日志、调试和行为评估；
- 不能代替国家作出宣战决定。

## 4. 最后通牒：用户有意设计的下一阶段正式机制

### 4.1 当前结论

用户明确有意好好设计“最后通牒”。现阶段不要把它当成已经完成的战争机制。

当前 `ultimatum` 已具备的部分能力：

- 能被识别为一种外交意图；
- 通常要求 `binding`；
- 会作为正式宣言传播、归档并进入外交记忆；
- 通常要求目标国回应；
- 会增加战争压力；
- 可以算作一次实质性外交推进。

当前缺失的核心能力：

- 没有结构化的具体要求；
- 没有结构化的到期时间；
- 没有绑定的违约后果；
- 没有接受、拒绝、部分接受、反提案的正式结算状态；
- 拒绝或超时后不会自动创建“兑现威胁还是退让”的后果决策；
- 发布国撤回威胁没有信誉代价；
- 同一矛盾可以被原样再发一次最后通牒。

因此当前最后通牒更接近“措辞强硬的、必须回应的宣言”，还不是完整外交契约。

### 4.2 推荐的数据语义

最终字段名可以调整，但正式最后通牒至少需要表达：

```text
ultimatum_id              本次最后通牒的稳定身份
source_document_id        来源公文
source_chain_id           所属提案/争端链
source_version            发布时所回应的最新版本
issuer_kingdom_id         发布国
target_kingdom_id         目标国
demand                    对方必须完成或接受的具体要求
deadline_day              到期日
failure_consequence       拒绝或逾期时宣称将采取的后果
response_state            pending / accepted / rejected / countered / expired
resolution_state          unresolved / fulfilled / consequence_chosen / withdrawn
```

其中 `failure_consequence` 必须限制在当前游戏确实能执行、且当时合法的动作范围内。第一版最适合支持“拒绝或逾期后重新决定是否宣战”，不要一开始承诺制裁、赔款、割地等尚无可靠结算器的动作。

### 4.3 推荐的后果决策方式

最后通牒遭拒或到期后，不建议由压力阈值直接自动宣战；应创建一次专门的“最后通牒后果决策”生成任务。该任务只要求发布国正面处理自己已经公开作出的承诺：

- 正式兑现后果，例如明确输出 `declare_war`；
- 因新让步或新事实接受修订方案；
- 撤回或软化最后通牒，但必须明确承受信誉、关系或战略一致性方面的代价；
- 若世界状态已变化导致后果不合法，必须基于新状态重新判断，而不是机械执行旧动作。

这不是剥夺 LLM 自主权，因为 LLM 仍然决定是否开战；代码只保证它不能通过无休止重复最后通牒来逃避已经公开制造的外交后果。

为避免再次陷入单一话题，该后果任务只约束“必须处理这份最后通牒”，不要求正文必须出现固定词，也不规定只能宣战。它与普通自由开场任务应分开：普通回合自由选择议题，最后通牒到期则处理已存在的未决承诺。

### 4.4 必须防止的回归

- 不得把任何包含“否则”“最后期限”的普通正文直接机械升级为战争；
- 不得靠中文关键词决定最后通牒的具体法律效果；
- 不得在目标国尚未收到正式公文时提前结算拒绝或超时；
- 不得让第三国替目标国接受或拒绝；
- 不得让 AI 替玩家统治的王国处理最后通牒；
- 不得因旧响应任务延迟完成而结算错误版本；
- 不得在后果任务中重新注入巨大动态 system prompt，破坏缓存前缀；
- 不得在 Tick 热路径扫描全部历史文档寻找到期项，应维护限量索引或待处理队列。

## 5. 玩家宣言与传播知识的相关约束

这些问题不是本轮两个战争目标本身，但后续实现不能破坏已经确定的方向：

1. 玩家宣言必须优先进入相关国家的回应链，不能因为普通 NPC 任务、轮次关闭或传播延迟而丢失。
2. 玩家不需要手动指定所有目标国；目标来自宣言语义和参与国，但只有宣言传播到某国王庭后，该国才获得正式回应资格。
3. 宣言刚生成时，玩家左下角只收到模糊传闻，例如：

   ```text
   据传瓦兰迪亚王庭发布了一份面向巴旦尼亚的外交宣言，似乎涉及停战事宜。
   ```

4. 宣言传播到玩家所属王国的王庭后，不论玩家是国王还是封臣，玩家、国王和相应贵族同步获得正式公文与具体诉求知识。
5. NPC 不能只知道“有一份宣言”，还必须知道标题、类型、具体诉求、对象、来源和当前提案版本。
6. 玩家提前看到传闻不等于玩家王国已经正式收文；更不能因为公文后来到达王庭，就让 AI 以玩家统治者身份自动回应。

未来最后通牒的期限应从目标王庭正式收到可回应公文后计算或至少明确采用哪种计时口径，不能让传播时间吞掉回应期限。

## 6. 记忆、传播与缓存优先级

用户的首要性能目标仍是保持很高的输入缓存命中率。新功能必须沿用当前“稳定前缀 + 动态尾部”的结构，而不是把世界状态和公文正文不断塞进 system 前缀。

原则：

- 保留新开发者版本的提示词静态结构与记忆框架；
- 固定规则、输出契约和公共行为准则放在稳定 system 前缀；
- 当前回合、当前公文、传播知识、最后通牒状态等动态数据只放在靠后的动态消息中；
- 同一回合继续复用 `LlmTranscript`，不要每次重新拼接完整历史；
- 共同契约快照在合适边界冻结，MCM 修改只影响新快照；
- 已传播知识增量追加，不因每个游戏小时或每个 Tick 重建全部记忆；
- 历史压缩依据真实 token 预算和消息链增长触发，不能把“一个外交回合结束”误当作压缩条件；
- 压缩后保留事实、未决提案、具体诉求、来源版本、玩家发言和最后通牒状态，不能只剩一段模糊摘要；
- 新增最后通牒后果任务不应多发一次纯分类请求，尽量在原有生成任务结构中使用稳定的 `MODE` 和固定输出契约。

缓存验收不能只看百分比，也要同时记录：

```text
命中缓存输入 Tokens
未命中输入 Tokens
输出 Tokens
请求次数
单场外交平均未命中 Tokens
长时间游玩后的稳定命中比例
```

不能保证仅靠“玩得更久”自然逼近 99%。如果动态尾部持续增长、任务类型频繁切换、system 前缀变化或历史被整体重写，未命中仍会保持较高。目标应是相同任务共享尽可能长的稳定前缀，让新增事实只产生有限尾部未命中。

实施前保留可回退基线。如果改造后同等请求规模下未命中 Tokens 明显增加，应优先回退提示词和记忆拼装方式，再重新设计，不要为了保留新机制接受持续缓存退化。

## 7. 当前已完成或在途的相关修复

以下改动在当前工作区中存在，后续开发者不得因重写战争链而误删：

- NPC 君主面对面被玩家说服宣战时，可走直接口头外交标签，不再错误依赖已被接管禁用的王国外交议程；
- AI 外交接管开启时，前处理将战争、和平、同盟和贸易引导至 `DIPLOMACY`，而非 `KINGDOM_AGENDA`；
- 接管开启后，原版外交议程候选会被隐藏，迟到的旧外交议程标签也在执行边界被拒绝；
- 同盟拉参战等强制议程通知对同一项只自动弹出一次，关闭后不会每小时反复弹出，并保存到存档；
- NPC 君主的有限宣战后处理资格与完整外交后处理资格已经拆分，避免给不合格会话开放其他外交动作；
- 提案响应任务会绑定当前来源公文 ID、提案链 ID 和版本，防止迟到回复结算到新版提案；
- 宣言列表 UI 已在调整为黄色只显示标题、白字居中显示“外交宣言：类型”；
- 已移除会干涉正文自主表达的固定关键词式意图校验方向；合法性校验仍须保留；
- 当前记忆与传播适配、新知识注入和缓存改造已经存在在途修改，需通过差异审查确认后继续。

此前已经讨论、但尚未实施的“口头外交双模式重构”暂不属于本轮首要目标：

- AI 外交关闭：保留传统口头外交直接触发，不写入 AI 世界外交档案；
- AI 外交开启：未来可让国王将玩家谏言作为素材发布正式宣言，再进入传播和外交结算；
- 用户已明确暂缓“如何让与当前事件无关的国王合理嵌入现有回合”的设计。

## 8. 推荐实施顺序

### P0：建立可观测基线

1. 为每场回合记录开场依据、选择议题、选择意图、是否含战争矛盾、最高升级阶段和最终机械结果。
2. 记录最后通牒的生成、传播、回应、拒绝、超时和回合关闭原因。
3. 检查最后通牒战争压力是否重复记账。
4. 用当前版本保留缓存命中、未命中和请求次数基线。

### P0：补足战争矛盾来源

1. 设计稳定、限长的冲突机会摘要。
2. 接入真实领土、战斗、人物关系、外交背叛、政策和战略冲突事实。
3. 调整开场提示，让严重矛盾有机会成为主线，但不指定结论。
4. 验证不会重新退化为固定话题或长期只谈贸易。

### P0：设计并实现正式最后通牒

1. 先确定支持的要求、回应和失败后果范围。
2. 增加稳定身份、来源链、版本、期限和状态字段。
3. 将目标国的接受、拒绝、反提案与正确来源版本绑定。
4. 在正式收文后启动期限。
5. 拒绝或超时后排队一次专门的后果决策。
6. 由 LLM 选择兑现、修订或退让，C# 只校验并执行明确动作。
7. 防止同一最后通牒被原样重复发布来逃避结算。

### P1：让升级链与自然结束共存

1. 普通争端仍可通过让步、反提案、结盟、贸易或无结果结束。
2. 最后通牒不是每场冲突必经阶段，也不是宣战的同义词。
3. 一旦国家主动选择最后通牒，就必须处理其失败后果，不能无成本遗忘。
4. 回合硬截止可以关闭普通交涉，但不能静默吞掉仍未结算的最后通牒。

### P1：完成记忆和玩家传播链回归

1. 验证目标王庭收到的具体诉求进入 NPC 正式知识。
2. 验证玩家国王和封臣在正式收文时同步获得公文。
3. 验证玩家宣言回应任务优先且不会丢失。
4. 验证 AI 永远不替玩家统治的王国作答。

## 9. 验收标准

至少覆盖以下测试：

1. 和平开局连续观察足够多的外交回合，贸易不再压倒性占据主线。
2. 领土争议、近期战斗、文化故土、个人仇怨和敌对扩张能够成为真实战争矛盾来源。
3. 同一矛盾可以和平解决，也可以随拒绝和升级发展到正式宣战；结果由 LLM 选择。
4. `declare_war + binding` 且状态合法时真正改变游戏战争状态。
5. 最后通牒没有遭拒或到期前不会提前执行后果。
6. 最后通牒遭拒或到期后必定进入一次后果决策，而不是静默关闭或原样再发。
7. LLM 可以选择不宣战，但撤回或软化必须被记录为明确结果，而不是遗忘。
8. 不使用正文固定词表来决定外交类型或执行效果。
9. 提案、最后通牒和回应均绑定正确的来源公文、链 ID 与版本；迟到回复不能串线。
10. 被俘统治者不能发布新宣言。
11. 玩家宣言传播到目标王庭后优先获得回应；AI 不得替玩家作答。
12. 正式公文到达玩家王庭时，玩家与相关 NPC 同步知道具体诉求。
13. 参与国家数量继续服从 MCM 规模限制，不能因交由 LLM 选择而失效。
14. 同等测试规模下对比修改前后的缓存命中、未命中、输出和请求次数；若未命中明显恶化，执行回退审查。
15. 不在高频 Tick 中扫描全部王国、全部宣言或全部最后通牒。
16. 涉及 Bannerlord API 的代码修改后，`BannerlordApi=1.3` 与 `BannerlordApi=1.4` 双构建均通过。

## 11. 最终设计判断

本轮不是要通过硬代码“让战争数量变多”，而是补齐一条可信的外交因果链：

```text
真实矛盾被国家识别
        ↓
LLM 根据战略与局势选择交涉、施压或升级
        ↓
对方的回应造成真实的新局面
        ↓
严重争端可由 LLM 主动发布结构化最后通牒
        ↓
拒绝或到期后必须处理公开承诺的后果
        ↓
LLM 明确选择宣战、接受修订或承担退让代价
        ↓
C# 校验合法性并执行真实游戏机制
```

要解决的是“AI 没有值得开战的理由”和“AI 即使威胁也不必兑现”这两个底层问题。最后通牒应成为连接外交争端与战争决策的正式桥梁，但不能成为替 LLM 自动宣战的数值开关。
