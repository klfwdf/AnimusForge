# 外交宣言的近期上下文与输入预算

宣言请求使用“固定规则＋本次相关历史窗口＋当前动态材料”。窗口优先读取指定原公文、触发公文和当前事件最近发言，再读取近期相关双边公文及必要旧事摘要。完整长期档案继续保存和压缩，不作为每篇宣言的输入。

窗口最多20,000字符、16k估算token，并根据规则和动态材料大小自动缩小，为一次校验修复预留4096估算token。整个宣言请求及修复请求最多32k估算输入token；规则或当前公文本身过大时，本地终止发送并保留材料，不会继续发送巨量输入或重置修复次数。

长期压缩继续由现有MCM阈值触发，默认800k；压缩后档案目标默认48k。这两个数字描述档案积压和长期快照，不代表宣言每次读入的长度。压缩每批最多128k估算输入，按连续前缀处理，成功后推进覆盖点；后缀和压缩期间新增记录保留。单条不能容纳时保留档案并在本地退避。

升级后旧请求按协议29重建，已存在的摘要、政策来源去重和归档保存键保持。新窗口为运行期派生数据，不写入存档成为第二份历史。诊断中的historyEstimatedTokens仍为全局档案估算；requestHistoryChars和historyMode说明本次实际历史窗口。

上述上限针对本地估算的输入，不包含输出/隐藏推理，也不等同于提供商实际tokenizer或最终账单。验证、源码坐标和保留失败记录集中在[交付说明与验证边界](diplomacy-round-design/UPDATE_20261005.md)。
