# GCCZ 城镇整体重构功能改发列表

更新时间：2026-08-21  
适用范围：`GCCZ` 独立主体与 `NEW-10` AF 融合版本中的城镇处置流程

## 1. 重构目标

- 以 GCCZ 城镇现有功能为基础全面重构代码，不另建一套脱离 AF 的独立玩法系统。
- 重点优化 AI 提示词、人物台词、标签判断、场景反馈和过程呈现，让现有功能不再生硬。
- 保持旧版本 Mod、旧存档、旧标签和玩家既有认知连续，不因内部重构突然改变玩法结果。
- 所有主体逻辑留在 GCCZ；NEW-10 中的 AF 改动只保留薄桥接、数据传递、状态守卫和必要运行时副作用。
- 所有 C# 代码、标识符、文件名、注释、日志、内部键和测试名称使用英文。
- 当前玩家可见文本保持中文，集中放在本地化、提示词或说明书资源中，避免散落硬编码在业务类里。

## 2. 不可改变的兼容基线

以下项目优先级高于代码整理和表现优化：

- [ ] 现有正面结算的奖励、消耗、资格要求、数值门槛和完成要求保持不变。
- [ ] 现有负面结算的奖励、惩罚、消耗、资格要求、数值门槛和完成要求保持不变。
- [ ] 完整执行原有行为时，仍得到旧版本相同的完整结算结果。
- [ ] 不借重构名义重新平衡繁荣度、安全度、忠诚度、关系、犯罪度、声望、士气、金钱、物品或其他旧有结算项。
- [x] 在迁移实现前，先用回归测试或快照锁定旧版结算表、要求和关键条件。
- [x] 搜掠与血洗新增的按实际进度结算，只处理“中途喊停或只伤害部分目标”的新情况，不改变旧版完整行为的奖励和要求锚点。
- [x] 旧标签格式继续能够读入；兼容层只负责映射到新语义动作，不再作为固定关键词触发器扩散到新代码。
- [x] 旧存档缺少新增字段时使用安全默认值，不要求玩家重开档。

## 3. 明确保留或取消的内容

### 3.1 保留

- [x] 除入口规则提示外，原有亲自进城入口逻辑保持兼容。
- [ ] 市场完全遵循原版现有行为，不新建市场经营或独立交易系统。
- [ ] AF 已有玩家履历继续使用，不在 GCCZ 重复维护第二份玩家履历。
- [ ] 原有正面、负面处置功能继续存在，只优化代码组织、AI 选择和呈现方式。
- [ ] 伴随角色的主要人格依据继续来自 AF 生成的性格特点。

### 3.2 取消或禁止扩展

- [ ] 不根据攻城结果向 AI 描述破损城墙；当前有平民的完整城市场景按其真实画面叙述。
- [ ] 不制作大型城镇管理面板、独立经营循环或高成本“独立游戏式”系统。
- [ ] 不以同文化作为同伴和贵族反应的主要硬规则。
- [x] 不使用玩家台词中的固定词表直接决定语义标签。
- [ ] 不在 GCCZ 城镇活动范围之外注册全局行为或污染其他 AF 场景。

## 4. 功能改发清单

### 4.1 亲自进城入口呈现

现状问题：进入场景后连续弹出多条规则，像调试操作面板，打断代入。

改发方案：

- [x] 将连续规则弹窗收敛为一次简短中文入场提示。
- [x] 详细规则移入 MCM 的 GCCZ 城镇说明书，不在每次入城重复灌输。
- [x] 必须即时知道的状态通过一条自然旁白、通知或人物反应呈现。
- [x] 不改变原有入城资格、场景选择、人员带入、退出和结算入口。

### 4.2 六类对话对象

城镇对话上下文必须明确区分：

1. 随行友方贵族。
2. 贵族俘虏。
3. 玩家带入场景的同伴。
4. 城镇头人和其他要人。
5. 普通士兵。
6. 普通平民。

改发方案：

- [x] 每次请求 AI 前生成唯一角色类别，不允许依靠提示词猜测身份。
- [x] 不同类别拥有不同的可用背景、语气重点、可选标签和记忆范围。
- [x] 随行贵族、贵族俘虏、玩家同伴、头人和要人使用 AF 的具名人物持久记忆。
- [x] 普通士兵与普通平民只保存本次场景记忆；退出场景后清空，不写入长期人物记忆。
- [x] 无法可靠识别身份时回退到权限最低的普通场景角色，不越权生成贵族或要人动作。

### 4.3 城镇统治记忆

- [x] 为每个定居点维护独立的城镇统治记忆。
- [x] 记录当前统治者、统治文化、AF 生成的主要性格描述、统治开始时间和已持续时长。
- [x] 统治者或文化发生变化时保留必要的前任摘要，避免 AI 把新旧统治混为一谈。
- [x] 如果游戏开局以来一直由同一统治者控制且没有可用历史，提示为“已经统治至少两年”。
- [x] 城镇记忆只补足当地历史，不复制 AF 玩家履历。
- [x] 老存档没有城镇记忆时惰性初始化，并保证读取失败不会阻断进城。
- [x] 由 AI 根据统治者的 AF 性格与名声、文化和统治时长生成约 100 个汉字的当地共同记忆，并使用严格 JSON 输出协议验证结果。
- [x] 每座城镇最多保留最近三任统治者的共同记忆；同一统治者隔任后再次上台时按任期分别保存和编辑，超出的最旧任期删除。
- [x] 第一次与本城普通平民、头人、要人或城镇所有者对话，或打开城镇百科时，惰性生成尚缺失的现任记忆。
- [x] 城镇百科把城镇记忆追加在原有介绍下方；异步生成完成或开发者编辑后自动刷新已打开的对应页面。
- [x] 开发者模式可编辑最近三任中的任一条、清空后等待惰性重建，或强制重新生成现任记忆。
- [x] GCCZ 城镇平民的回答同时使用城镇共同记忆、自身身份、AF 无名人物随机性格和本场景记忆；退出后仍只清除普通人物的场景记忆。
- [x] 此扩展严格限制为城镇，不向村庄、城堡、普通世界地图对话或无关 AF 功能注入。

### 4.4 AI 提示词与低注意力模型适配

目标：让 DeepSeek 等注意力较弱的模型也能稳定理解当前角色、场景、可执行动作和标签格式。

- [x] 提示词改为短小、固定顺序的分段结构，不堆叠长篇重复规则。
- [x] 顺序固定为：当前场景、说话者身份、有效记忆、当前状态、候选动作、禁止动作、回答要求、输出格式。
- [x] 使用清晰的角色与场景矩阵，明确每类人物“知道什么、记住多久、能做什么”。
- [x] 每次只提供当前状态真正允许的候选标签，不把全部 AF 标签塞给模型自行排除。
- [x] 要求模型先根据语义判断玩家意图，再选择零个或一个主要动作标签。
- [x] 将严格输出格式放在提示词末尾，靠近模型实际输出位置。
- [x] 添加少量短正例和反例，重点训练相似标签边界、无动作回答和拒绝越权动作。
- [x] 人物回答必须先符合身份、AF 性格和现场经历，再附带机器可读标签。
- [x] 当对话只是闲聊、询问或情绪表达时允许不输出功能标签。
- [x] 后处理仅进行格式解析、别名归一化、状态校验、拒绝和安全回退，不用关键词重新猜测意图。
- [x] 保存低注意力模型测试样例，覆盖误选标签、漏标签、多标签、正文包含标签词但无执行意图等情况。

### 4.5 AI 语义标签路由

核心原则：标签是交给 AI 判断的动作协议，不是固定词触发器。

正常城镇处置阶段可按人物资格和当前状态提供：

- [x] GCCZ 城镇专用动作。
- [x] 情绪和态度类动作。
- [x] 普通知识、历史和询问类动作。
- [x] 合法的资产、交易和债务类动作。
- [x] 仅对合资格具名 Hero 开放的加入、效忠类动作。
- [x] 合法的政治、议程、外交、婚姻和任务类动作。

正常城镇处置阶段仍需阻断：

- [x] 普通决斗标签。
- [x] 场景跟随、召唤和带路标签。
- [x] 队伍转移标签。
- [x] 遭遇释放和投降标签。
- [x] 领主大厅切换标签。
- [x] 普通场景嘲讽、转述和贵族聚集标签。
- [x] 世界地图命令标签。
- [x] 其他会与 GCCZ 当前场景所有权或处置状态冲突的动作。

血洗或殖民战斗进行时：

- [x] 只向 AI 提供 GCCZ、情绪、生存、求饶、制止和战斗现场相关候选动作。
- [x] 暂停交易、婚姻、任务、效忠等不符合现场状态的动作，结束战斗状态后再恢复。

### 4.6 人物台词与性格反应

- [x] 随行贵族和同伴反应主要使用 AF 生成的性格特征、彼此关系、玩家行为和现场记忆。
- [x] 贵族俘虏重点表现其俘虏身份、尊严、恐惧、交易价值和对玩家行为的判断。
- [x] 头人和要人重点表现其职业、当地利益、个人风险和城镇统治记忆。
- [x] 士兵反应使用命令状态、阵营、士气和本场景已发生事件，不生成跨场景长期人生记忆。
- [x] 平民反应使用恐惧、安全感、目击事件和本场景玩家行为，不生成跨场景长期记忆。
- [x] 同文化只作为可选背景信息，不覆盖 AF 性格或现场因果。
- [x] 相同动作根据人物性格给出不同但不改变结算要求的表达。

### 4.7 正面与负面结算呈现

- [x] 完整保留现有正面和负面行为列表。
- [x] 完整保留每项行为的奖励、惩罚、消耗、前置要求和完成要求。
- [x] 优化 AI 对行为意图的理解，减少生硬菜单式台词。
- [x] 将执行结果拆成自然的命令确认、人物回应、现场反应和最终结算提示。
- [x] 呈现层不得重复发奖、提前发奖或绕过旧要求。
- [x] 同一动作的 AI 表达可以变化，但最终调用唯一的旧版兼容结算入口。

### 4.8 灵活搜掠

必须区分以下目标：

1. 全城搜掠。
2. 抢劫商人 NPC。
3. 抢劫头人或其他要人。
4. 抢劫一定数量的普通平民。

改发方案：

- [x] 使用一次行动账本记录唯一目标、实际获得物、已施加后果和行动状态。
- [x] 普通平民按实际被抢人数计数，不按场景理论总人数结算。
- [x] 商人、头人和要人使用独立目标权重，不能伪装成普通平民重复计算。
- [x] 玩家喊停后立即停止后续抢劫，但已抢物品和已产生惩罚不回滚。
- [x] 重新开始时继续使用同一账本，不重复发放同一目标的奖励。
- [x] 完整全城搜掠仍使用旧版完整奖励、惩罚和要求。
- [x] 将本次实际取得的金钱与物资估值除以本次可搜掠物资总估值，得到限制在 `0%` 至 `100%` 的累计搜掠比例。
- [x] 部分搜掠的奖励和惩罚按累计搜掠比例折算；`100%` 必须严格等于旧版完整搜掠奖励和最高惩罚，`0%` 不产生搜掠结算。
- [x] 商人、头人、要人和平民只决定物资来源、现场反应和账本归属，不再各建一套随意数值表。
- [x] 分阶段搜掠只补发累计比例新增部分，禁止每次交互都按总比例重复结算。
- [x] 部分搜掠只在旧版完整结算边界内折算，不建立新的整体平衡表，也不改变原有完整搜掠触发要求。

### 4.9 可喊停血洗

- [x] 血洗开始后记录本次行动目标快照和唯一受害者标识。
- [x] 普通平民按实际死亡人数结算。
- [x] 头人和要人单独计数并使用更高权重，不能重复计入普通平民。
- [x] 部分血洗的后果从旧版最高搜掠后果基线开始，随实际死亡规模增加。
- [x] 完整血洗保持旧版完整结算值和要求，不重新平衡。
- [x] 玩家在完成前可以喊停；喊停只终止未来杀戮，不复活死者、不撤销已产生后果。
- [x] 停止后士兵停止搜寻和攻击，幸存者保持恐惧、逃跑或中立，不瞬间恢复日常状态。
- [x] 再次下令时沿用同一行动账本，已经结算的死亡不能再次领奖。

### 4.10 殖民状态机

- [x] AI 标签触发殖民时先进入明确的待执行状态。
- [x] 玩家触发标签后直接退出场景，立即执行旧版兼容的完整殖民结算。
- [x] 玩家留在场景时，士兵对触发时捕获的相关平民、头人和要人目标快照执行行动。
- [x] 所有目标死亡前，玩家可以喊停；此时取消殖民，只按已经发生的死亡结算为部分血洗。
- [x] 所有有效目标死亡后锁定并执行一次完整殖民，不再接受喊停回滚。
- [x] 目标快照为空时不得因为 `0/0` 自动完成殖民，必须走安全回退或退出结算规则。
- [x] 文化变化、奖励和惩罚必须只提交一次。
- [x] 存档和退出恢复时能够识别待执行、已取消和已提交状态，避免重复结算。

### 4.11 普通文化变更

- [x] 增加独立于殖民的定居点文化变更功能。
- [x] AI 提示词、标签、要求、台词和说明书必须明确区分“普通文化变更”与“殖民”。
- [x] 普通文化变更不自动继承血洗、殖民或搜掠语义。
- [x] 实际结算遵循既有正负面奖励和要求兼容原则，不因新呈现层偷偷改数值。
- [x] 变更成功后同步更新城镇统治记忆中的文化信息。

### 4.12 躲藏平民的带出机制

- [x] 玩家要求把躲藏居民带出来时，只生成数量受限的小批平民。
- [x] 优先选择安全、可导航、远离玩家正面的场景角落生成。
- [x] 生成前检查现存人数和本次行动账本，防止反复命令无限刷人。
- [x] 新生成平民加入本次场景记忆和相关行动目标，但退出场景后清空普通角色记忆。
- [x] 生成失败时给出自然中文反馈，不影响市场和其他原版场景逻辑。

### 4.13 MCM GCCZ 城镇说明书

- [x] 在现有 MCM GCCZ 分组顶部增加“城镇说明书”入口。
- [x] 使用分页或分段中文文本，避免一个超长弹窗。
- [x] 第一版只写城镇功能，不提前混入城堡和村庄说明。
- [x] 内容覆盖：进城、六类人物、记忆期限、躲藏居民、正面处置、负面处置、搜掠、血洗喊停、殖民、普通文化变更、AF 标签开放与阻断、退出行为、日志诊断。
- [x] 说明书内容放在资源文件中；MCM C# 只负责入口与显示。
- [x] 说明书只解释真实实现，不写尚未完成或不存在的功能。

### 4.14 NPC 环境回应限额

- [x] 玩家直接交谈对象的正常回复不受环境回应额度挤占；周围 NPC 的接力回应统一受 MCM“NPC回应数量限制 / NPC回应无限数量”控制。
- [x] 普通玩家发言、集体喊话、GCCZ 语义动作、正负面处置、召集平民、搜掠、血洗、殖民、普通文化变更和玩家攻击目击反应使用同一事件预算。
- [x] 有限模式下，每个独立玩家话语或游戏事件最多允许设置数量的唯一 NPC 发起 LLM 请求；额度耗尽后停止创建、入队和重试请求。
- [x] 无限模式只取消 MCM 数量上限，仍受场景实际人数、同一说话者每事件一次、队列容量、并发限制、去重和退出清理约束。
- [x] NPC 生成的回应不得创建新的环境回应事件；重复标签、重复命中和队列重试继续使用原事件标识，不形成自我繁殖的对话链。
- [x] 新配置默认使用有限模式；旧配置已保存的无限值继续由 MCM 正常读取，不伪造无法可靠判断的存档迁移。
- [x] 退出 GCCZ 城镇时清空事件预算、排队请求、节流键和普通人物场景记忆，不影响非 GCCZ 场景。
- [x] 诊断日志只记录事件标识、配置上限、允许/拒绝数量和拒绝原因，不记录完整提示词或玩家原文。
- [x] 回归测试覆盖有限 1/N、无限、零对象、重复说话者、重复标签、重复命中、回应不再触发回应、队列上限、退出重置和非 GCCZ 隔离。

## 5. 代码隔离与重构结构

- [x] GCCZ 主体保持单一事实源，NEW-10 不复制第二套业务规则。
- [ ] AF 桥接只传递场景上下文、人物身份、AF 性格、记忆引用、候选标签和执行结果。
- [x] 将提示词编排、候选标签路由、角色分类、场景记忆、城镇记忆、行动账本、状态机、结算适配和中文资源加载拆分为窄职责组件。
- [ ] 使用明确状态转换代替散落的布尔值组合。
- [ ] 每个奖励或惩罚只允许通过一个结算适配入口提交。
- [x] 保存数据增加版本字段和默认迁移，不破坏旧存档读取。
