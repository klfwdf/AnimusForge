# AF 2.0 收尾交付计划

状态：INTEGRATION_HANDOFF_READY（仅候选/接入/离线；v1.3.5、v1.4.5 的 U1–U9 实机仍未签收）

## 1. 目标与范围

**完成当前版本的使用验收和制作组接入交付。旧宿主后续渐进拆分，不作为交付前置。**

- 本轮只做：候选核对、接入说明、实际阻塞修复、验收交付。无阻塞就不改产品代码。
- 不做：大宿主瘦身、全接口统一、全仓审计、通用插件平台、新玩法。
- 保持：三渠道语义、权威动作与记忆提交、线程/代际保护、存档与程序集身份、双版本单模块输出及原构建流程。
- 制作组走同 DLL typed internal 接缝；独立子 MOD 走版本化 public API。新业务归模块，不向宿主增加业务状态；公共 V1 不扩展 ActionExecute / MemoryWrite / ExtensionRegister。

## 2. 执行步骤

| 阶段 | 工作 | 出口 |
| --- | --- | --- |
| R0 冻结候选 | 核实 main、工作树、构建输入和产物；明确 SessionTransport 未提交改动是否属于候选；冻结 B0–B3、U1–U9 的版本、样本、预期、证据和负责人 | 候选与验收卡完整，阻塞清单确定 |
| R1 接入说明 | 修正内部指南旧路径和三渠道状态；写清内部/公开入口、上下文、线程、结果、取消、限制和已有示例 | 制作组可按说明接入，不必阅读大宿主内部 |
| R2 阻塞修复 | 复现具名问题，修最小相关代码与消费者，定向验证；无阻塞则跳过 | 冻结范围内无未处理阻塞，修复证据有效 |
| R3 验收交付 | 按下表补缺口、复用有效证据；交付修订、产物、使用说明、限制和恢复方式 | 达到第 5 节对应出口，结束本轮 |

R1 可与修复、验证准备并行。阻塞仅包括：加载/主要链路不可用、当前接入失效、错误目标或重复效果、数据/隐私风险、生命周期错误，以及阻断固定流程的严重卡顿。

**验收卡在执行前填写：** ID、候选/产物 hash、精确游戏版本、入口/前置状态、输入/步骤/样本、预期结果、证据/命令、负责人、适用理由。B3 另绑定生产符号与 runner ID；U8 固定模块 AF 接缝名单。缺项不能签收，不得测完后降低预期。

## 3. 固定验收清单

### 3.1 交付与离线验证

| ID | 检查项 | 通过条件 |
| --- | --- | --- |
| B0 | 候选一致 | 源码、dirty 归属、引用/配置/资源输入和两实现/Bootstrap 产物 hash 对应；含 dirty 输入的 DLL 不冒充纯 main 产物 |
| B1 | 接入说明 | 内部与公开指南符合当前签名、能力和限制；入口、上下文、结果/取消、示例及验证路径准确、引用有效 |
| B2 | 构建兼容 | 同候选 Debug/Release 两 API 与 Bootstrap 构建证据有效；单模块/唯一加载、API 与保存身份检查无本轮未处理回归 |
| B3 | 行为证据 | 三渠道提交/结果、内部端口及失败语义有当前生产逻辑证据；覆盖重复、开始前取消、旧 owner/generation、迟到、部分/未知效果和唯一事实提交；修复风险有对应反例 |

### 3.2 有限使用验证

每个声明实测的游戏版本执行一次完整流程。允许同一次操作覆盖多项，不遍历全部 NPC、地点、标签和模块组合。

| ID | 样本 | 通过条件 |
| --- | --- | --- |
| U1 | 启动并载入一次测试战役 | 对应版本唯一实现加载，资源和启用入口可用，无阻断流程的加载错误 |
| U2 | Native 正常对话一轮 | 目标/输入正确，有真实终态回复；历史角色、记忆符合预期，无串人、重复提交或内部标签泄漏 |
| U3 | Scene 双 NPC 回合一次 | 参与者、回复、历史及顺序符合冻结预期，玩家输入不重复，事实归属正确 |
| U4 | Courier 发送至到达/回信一次 | 收件人正确，预生成不提前提交；终态、历史、记忆和回执一致，无重复提交 |
| U5 | 一个已有共同动作，适用渠道各一次成功与资格拒绝 | 成功有真实效果和对应事实；拒绝无越权效果或成功事实；同类语义一致，合法差异预先写明 |
| U6 | 三渠道各一份取消/迟到反例，实机补一次离场/关窗 | 未开始取消无执行；已开始的部分/未知结果不假称回滚；旧结果不污染新会话、不二次执行。具名离线反例可复用 |
| U7 | 测试档保存/读取一次；旧档兼容另测一份代表性旧档副本 | 冻结的状态/记录读取后一致，无相关损坏或重复效果；不拿新档替代旧档证据 |
| U8 | 冻结的模块 AF 接缝，每项一条现有路径 | 参数、结果和退出符合契约；仅验接入面，不重验模块全部玩法，不新造演示功能 |
| U9 | 随上述流程观察依赖与异常 | 所需网络/索引/资源可用；启用 TTS 时测一次输出与退出；无阻断流程的卡死、持续重复任务或明显残留，不另加压力测试 |

两 API 构建支持保留；实机结果逐精确版本登记。独立 DLL 实机使用若在本轮承诺内，须将真实消费者加载纳入 U1/U8，不能只用内部调用或元数据证明。

## 4. 证据与范围控制

1. **结果状态：** PASS、REUSED_PASS、FAIL、NOT_RUN、BLOCKED，或有理由的 N/A。保留预期/实测、输入、命令/操作、日志及替身边界；目录存在、总 runner 退出成功不等于本项通过。
2. **证据复用：** 输入、依赖、配置及覆盖范围一致才可 REUSED_PASS，并引用原收据。离线 fixture 不替代实机；U6 的离线反例与 U8 的接缝补证单独标注。
3. **定向重验：** 文档改动只验文档；产品改动重验失败项与受影响项，按原流程验证两 API/受影响构建。测试使用现有 runner；--ids 接收 ID 清单文件，输出隔离，路径开工时核实。
4. **不得放宽：** 不删断言、刷新 hash、重分类失败或更换样本掩盖问题；PREEXISTING_FAIL 不算通过。缺环境、权限或旧档不能改 N/A；不能关闭功能来缩小承诺。
5. **增项条件：** 只有本轮变更、具体失败或新运行证据才增加对应检查，写明“证据→受影响卡→最小验证”。新能力、完整模块玩法和架构治理另行决定。
6. **风险处理：** 新发现严重数据/安全风险必须披露并暂停受影响交付；不自动扩大为全仓改造。影响不明先查实际调用关系，不默认重跑全仓。

## 5. 交付出口

| 状态 | 必须满足 |
| --- | --- |
| INTEGRATION_HANDOFF_READY | B0–B3 全部 PASS/有效 REUSED_PASS，冻结的接入用途无阻塞；交付指南与实机未验清单，制作组可开始接功能 |
| USE_ACCEPTED（版本/范围） | 上述条件成立，声明版本的 U1–U9 适用项全部 PASS/有效 REUSED_PASS，无相关 FAIL/NOT_RUN/BLOCKED |
| 发布/部署完成 | 取得对应授权，完成包/依赖/许可/隐私检查及实际操作，核实远端 ref 或部署结果 |

缺实机条件就交接候选及未验项，不写 USE_ACCEPTED。只测一个版本就只报告该版本；完整双版本使用通过须两边均满足。

**达到出口立即结束。** 不追加常驻审核、全仓盘点或宿主拆分。交付保留已验证旧候选与测试档副本；恢复时使用完整候选包，不混 DLL、不覆盖玩家原档，不假定新档可由旧版读取。

## 6. 分工与权限

- 主控 GPT-6 Astra / medium（gpt-6-astra）：冻结范围、分派任务、处理冲突、判断出口。
- 交付及修复执行者 GPT-6 Sol / medium（gpt-6-sol）：默认一人负责 R0/R1/R3、共享接线、Git 索引和集中构建；存在具名阻塞时再派修复执行者，不预设多条重构线。
- 用户已授权按 R0–R3 执行仓内修改、测试、修复及本地检查点/验证切片提交；包内正常工作不逐步请示。
- 一文件一写者。任务卡包含精确所有权、输入、依赖、约束、验证、出口与权限；执行者独立完成读取、实现、测试和修复，只报告完成、真实阻塞或范围变化。
- 保护 SessionTransport dirty、其他作者改动及现有产物；产品实改按仓库规则建立本地检查点，不重写历史。
- 本计划不新增推送、Stage、打包、部署、仓外写入、真实玩家数据、批量清理或全局配置授权。
