# 可选多智能体执行计划：总控分包，执行者一次做完

> 2026-09-30，计划文档，尚未启动任务。仅在用户选择多智能体执行时启用；不是 AGENTS/Skill，不自动应用于其他会话，不创建自动化。
> 本文只定义协作方式，不定义 J17 或其他业务阶段的范围、进度和出口。业务计划可以由单人、单智能体或多人完成，不以启用本文为前提。

## 1. 目标和非目标

- 目标：总控一次给出可完成的任务包，执行模型直接完成读取、实现、接线、定向验证与交付，不在每个小步骤等审批。
- 不建立“规划代理→审核代理→执行代理→复审代理”的流水线；不常驻专职复审代理，不为凑并发重复派同一任务。
- 不降低业务验收标准，不把未运行的测试标为通过，不把转发壳、名称归类、文档数量当成果。
- 本次只编写计划；不因此启动代理、修改产品、推送、部署或恢复自动化。历史交接中的固定模型、人数、停点与授权不自动恢复。

## 2. 人员与权限

| 角色 | 职责 | 不做什么 |
| --- | --- | --- |
| 总控 1 名 | 确认当前任务/基线，分包与资源调度，处理跨包接口，合并交付，统一验收和进度记录 | 不重做每个执行者的完整审查；不逐 helper 审批 |
| 执行者若干 | 独占所属修改范围，一包从最小必要读取到真实结果与验证连续完成 | 不擅自扩大范围，不写别人的文件，不派重复子任务 |

- 启动建议为 3 个执行者；有足够独立工作包时增加至 5 个。人数服从实际工具并发额度、文件冲突和机器负载，不是固定门禁。
- 模型默认沿用当前配置，用户明确指定时才覆盖；不把某个模型名称或思考档位写死为前置条件。
- 子任务使用当前任务内的子智能体；未明确要求时不创建用户侧新会话。执行者需要再次拆包时交总控决定，避免层层派生。
- 总控独占共享工作树的 Git 索引、提交操作及正式台账/代码范围图/HANDOFF。不得回滚其他人的改动。

## 3. 启动一次，按增量分包

1. 总控确认工作区、分支、HEAD、dirty、授权范围和当前业务出口；读取当前入口，不逐页重读全部历史。
2. 需要清单时统一生成一次，记录源码/项目/条件编译/依赖基线。成员 ID 使用路径、类型、成员种类及完整签名，行号只用于定位；两 API 差异分别保留。
3. 复用仍有效的证据：只有相关源码、消费者、配置、依赖、工具链变化或具体失败才使对应部分失效；HEAD 改变不自动废弃全仓证据。
4. 按可独立验收的职责闭包拆包，列依赖与读写集合。接口、共享状态或大宿主改动高度耦合时合成一个包，或前后串行；不按等行数硬切。
5. 每包开工前一次固定完成条件和必要测试。不能因为“还可以再细分”无限加门槛；新发现的真实问题按第 7 节处理。

业务清单和进度沿用该任务的既有台账，不复制第二份状态源。总控只发待完成的包，不让多个执行者各自重新盘点全项目。

## 4. 一次下发的任务卡

每张任务卡必须填完再派发，不把模板占位符直接交给执行者：

```text
任务 ID / 目标：一个可验收的结果；明确只读审查还是允许修改。
基线：工作区绝对路径、分支、修订、需保留的 dirty。
所有权：允许写入的文件；混合宿主的符号范围；禁止写入的共享文件。
最小上下文：适用指令、真实入口/消费者、有效证据及其定位。
依赖：已交付输入、冻结接口、前置包；未满足者不能进入实施。
不变量：必须保留的行为、兼容/保存/线程/性能及排除范围。
完成条件：真实实现或审查闭包、全部受影响消费者、必要反例与测试。
验证资源：已确认的命令、工具链、独占输出目录或串行资源。
授权边界：不能做的外部写入、删除、推送、部署、真实用户数据操作。
交付：改动路径/符号、结果、命令与退出码、证据位置、未验项/阻塞。
执行约定：你不是唯一执行者；保留他人改动，遇到交叉修改先报告总控。
```

总控下发后，执行者直接完成包内工作，不只返回建议或下一步计划。只读审查包的成果是覆盖结论及具名缺口；实施包的成果是接线后的代码与实际验证。

## 5. 执行与调度

### 正常流程

`READY → RUNNING → DELIVERED → ACCEPTED`

- `DELIVERED` 表示执行者已完成任务卡；只有总控核对交付和必要集成门禁后才 `ACCEPTED`。
- 执行者连续完成：读取相关实现 → 实现/审查 → 验证 → 修复自己引入的失败 → 提交结果。不逐文件写长报告。
- 一个包交付后即可验收并释放依赖，不等所有包齐头结束；总控只分配输入已准备好的下一包。
- 进展通知只在交付、真实阻塞、接口变化或长任务的重要里程碑发生；不频繁轮询或播报无变化状态。

### 文件和产物冲突

- 只读任务可共享同一工作树。同一工作树内，每个文件同时只允许一个写者；同一大文件不同符号也不同时写。
- 多包需要改同一宿主时，由具名集成包统一接线，集成完成前相关实施包不算最终完成；或直接串行处理。
- 确需隔离时，先检查并优先复用可用工作树；新建受管理工作树须符合当前授权和写入边界。工作树隔离不能消除接口/状态依赖。
- 测试的 `bin/obj/.generated`、日志、临时资料、端口、Stage 也是资源。只有读过 runner 并确认输出隔离后才并行；固定输出或全量构建由总控串行安排。
- 执行者不操作共享索引。需要本地检查点和提交时由总控按仓库规则集中完成，禁止 `git add .`、重写历史和清理他人材料。

## 6. 一次集成验收，不循环复审

总控每包只做一次交付核对：改动是否在范围内、任务卡完成条件是否满足、真实 diff/消费者是否接通、测试是否绑定当前源码、跨包接口是否一致。

- 执行者已提供有效日志且输入不变的定向测试，不由总控机械再跑一遍。
- 合并改变了相关输入、两个包触及同一契约、出现冲突或具名失败时，只补受影响的验证。不同基线的结果不能拼成同候选通过。
- 产品要求的双版本、保存/ABI、安全等门禁保持；共享构建集中执行并记录其覆盖的包。需要本包构建才满足出口时，不为并发把它跳过。
- 全量回归按业务计划在最终候选或明确影响面触发时运行，不为每个 helper 跑一次；本文不能覆盖更严格的当前业务要求。
- 验收通过即关闭，不再把同包发给另一模型“再看一遍”。只有具体缺陷、证据矛盾、输入变化或明确用户请求才重开受影响部分。
- 失败返回原执行者的是“缺陷 + 复现/失败信号 + 预期结果”，不是“重新全面审核”。修复后只验失败与受影响项；无法收敛时按阻塞处理，不无证据反复重试。

## 7. 阻塞、异常与恢复

- 任务卡依赖不满足、其他人改了所属文件、缺少环境或验证失败无法定位：该包标 `BLOCKED` 并给出精确原因，总控让其他无关包继续。
- 总控可在当前授权内调整文件所有权/顺序；新玩法、数据破坏风险、外部写入等越界问题必须请用户决定，不能借“效率”默认同意。
- 发现与当前包无关的问题：登记具名后续项，不阻塞本包。发现会使当前结果不正确的问题：补入当前有限出口，不假装通过。
- 超时或代理失联：先确认进程、文件和输出状态，停止原写者后才交接给替补；不得让两个代理继续写同一包。
- 接续时只移交任务卡、已完成差异、证据和下一步，不重跑无变化的已验部分。

## 8. 交付与结束

执行者一份短回执：任务 ID、基线/实际输入、改动与消费者、验证命令/退出码/日志、未验项、阻塞（无则写无）。敏感日志只给安全位置，不复制凭据或玩家原文。

总控统一更新业务台账和简短交接，报告：已接受包、剩余包、实际失败、未验范围；不能把文档落盘或代理结束等同于产品完成。

效率只看完成的责任包、未知项净减少、关键路径和有效验证；不按代理数量、报告篇数、测试重复次数计功。不承诺固定加速倍数。

停止条件：当前授权范围的工作包全部达到有限出口，或仅剩需要用户/外部条件的精确阻塞。不得自动追加新审计轮、扩大业务范围或启动后台监控。
