# 外交政策历史重复增长修复（2026-09-06）

## 原因与改动

玩家政策的 `ImpactEffectsSummary` 是动态展示文本，包含每日递减的剩余天数。外交曾把它作为发布正文计算内容哈希，再把全表内容哈希当成账本身份。倒计时变化因此同时触发全表重同步和政策全文追加。

- 玩家政策导出新增独立的外交归档摘要，在展示截断之前生成不含倒计时的状态文本；原来的实时摘要仍供其他检索和 UI 使用。
- 政策效果实例、期限以及地方/附庸政策续期次数参加语义版本判断；政策状态、效果结束状态和实际效果正文仍可产生变化。
- 政策快照使用稳定账本 ID，内容版本只决定是否重新检查快照。外交按政策 ID 保存最后指纹与递增事件号，支持 A → B → A，且压缩、存读档后不重放。已知政策的新状态记为 `policy_snapshot`，用观察当天日期；首次发布保留来源日期。
- 存档初始化执行一次倒计时副本迁移。只合并同一政策、同一事件上下文、正文与效果完全相同且所有剩余天数不增加的相邻观察；期限改变、倒计时增加、事件类型改变、效果/正文修改、到期和废除均保留。按最后一次观察比较，避免误删 100 → 90 → 95 的续期。序号不重排，外交事件与结果不清除。
- 已压缩的自由文本摘要没有可靠的逐条来源，迁移保留它；后续正常压缩继续管理其长度。旧格式升级后允许补入一次当前稳定状态基线，不把旧倒计时文本当成新格式的去重指纹。
- 清除待发送修复请求中独立保存的旧历史副本，让请求从当前档案重新生成。

## 输入长度保护

发送前按已有本地估算器检查全部消息（包含规则、历史、动态状态和消息开销），使用现有 MCM 的外交压缩触发值作为发送上限，不更改用户设置。超限宣言等待压缩，不消耗一次 API 请求或每日请求次数。

压缩也选择能容纳的连续历史前缀，发送截止序号与提交截止序号一致；后缀及请求运行期间新追加的记录保留。压缩成功释放等待标志，宣言重新检查总输入，避免持续安排压缩而无法恢复发送。每日请求预算耗尽时在构造大请求之前退出。

单条历史或旧摘要本身无法容纳时，不截断、不丢弃档案，也不反复付费压缩已经足够短的前缀：本地记录原因并按游戏时间退避。自定义非历史提示词自身超限时，本地终止该请求。此上限是本地估算值，不等于提供商的实际 tokenizer 计数或自动推断出的模型上下文上限。

## 性能与边界

沿用外交每游戏小时的来源同步和发送时强制同步入口，以及政策接口的一秒缓存与最多 400 条来源快照。仅语义版本改变才重置快照游标；稳定指纹查询使用字典。迁移只在旧存档初始化时扫描一次；输入计数、分批选择发生在请求准备/压缩入队阶段。没有增加每帧全历史去重、文件读取、反射或外部 API 调用。

本修复处理外交历史，不更改政策机械执行、MCM 检索开关、三渠道对话或游戏覆盖脚本。

## 离线验证

- `tools/WorldDiplomacyPolicyHistory.SmokeTests`：158 项检查，包括 60 天去重、续期、到期、废除、A → B → A、序列化后去重、迁移幂等、连续压缩前缀和无进展保护；包含对刚编译的 1.4 DLL 归档渲染器的直接回放。
- 用户请求样例（只读，不收入仓库）：未压缩记录 556 → 76，移除 480 条倒计时副本；这些记录的正文 328,581 → 30,988 字符。原压缩摘要和非政策记录保留。这不是整个请求的最终 token 数。
- `WorldDiplomacyCompression.SmokeTests`：269 项通过。
- `WorldDiplomacyIntentBoundary.SmokeTests`：1,168 项通过。
- 使用现有 `build_single_module.ps1`，1.3、1.4 和 Bootstrap 编译通过；引用版本分别验证为 1.3.15 与 1.4.6。产物位于 `bin/Debug/single_module_artifacts`。

回放命令（第二个参数可选，提供时检查编译后的归档渲染器）：

```powershell
dotnet run --project tools/WorldDiplomacyPolicyHistory.SmokeTests -- <request.json> <AnimusForge.dll>
```

没有调用真实 LLM、修改反馈者的请求样例或存档，也没有部署到游戏。游戏内加载旧存档、推进日期及实际外交发送仍需实机验收。
