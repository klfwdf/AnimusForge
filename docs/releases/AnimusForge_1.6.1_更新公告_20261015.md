# AnimusForge 1.6.1 更新公告

日期：2026年10月15日

本次更新以 **10月13日发布的 1.6.0** 为基线，汇总之后的新增功能与修复。重点是让人物对世界变化产生更持久的反应，让 NPC 的来意更贴近玩家经历，并完善外交、对话编辑、新闻和数据保存。

## 人物会因经历改变，也能直接编辑扩展人设

- 人物编辑器新增扩展人设编辑，可修改核心特质及强度、当前动机、重视的原则、弱点与恐惧、说话风格。
- 新增“事件驱动的 NPC 人设演变”。相关人物遭遇领地易主、亲属死亡等已记录事件后，系统会结合原有性格评估是否形成持久变化，并显示最近一次变化的简短原因。
- 开关位于终端 **外交与国家 → 周报与快报 → 事件驱动的 NPC 人设演变**，默认关闭，需要启用快报模式；不要求开启自动出版。
- 同一人物的相关事件会先合并，最早等待 **10 游戏小时**后排队评估。没有新事件就不会定时请求 AI，事件也不一定造成性格变化；大量事件会分批处理。
- 自动演变目前只更新扩展人设，**不会自动改写历史背景，也不会让 NPC 自行复仇、调兵或发动战争**。手动编辑后，后续事件仍能在新设定上继续产生影响。
- 修复重新生成人物设定时，AI 已返回个性与背景，却因返回结构不同而报解析失败的问题。

## NPC 会更有理由来找你

- NPC 主动接触新增“谈论玩家经历”和“回应玩家近况”两类来意。过去的重大经历、最近的胜负与其他有记录的行动，可以成为他们开口或来信的原因。
- NPC 可以表达好奇、请教、关心或质疑，不必每次都转回借钱、求物；原有求助、关系和政治动机继续保留。
- 这些反应遵守 NPC 的知情范围，并沿用接触冷却。不同渠道会避免反复拿同一件事开场，不会因为新增来意而提高整体接触频率。

## 新闻更像故事，旧闻也更有用

- 调整快报写作要求，鼓励围绕真实事件写出完整插曲、现场细节和人物反应；同一期最多合并三条重大事件。
- 取消仅因成稿包含战事数字就整篇退回简略内容的处理。报道仍以已确认事实为依据，不能改写胜负、生死、领地归属或外交结果。
- 重大快报事实可长期保留，并在 NPC 允许知道、与当前话题相关时被检索出来。超过近期窗口不再等于完全失去这些旧闻；旧存档只能恢复仍有可靠材料的部分。
- 修复关闭自动出版后，NPC 的快报事实来源受到影响的问题。自动出版与是否使用已有快报事实分别处理。
- 快报插画现在会参考已经生成的完整报道正文，更贴合文章中的叙事场景；修复导演文本含段内小标题时被误判为缺少构图内容的问题。
- 百科肖像不再把人物当前所在位置、眼前处境和当前年份作为画面要求。

## 外交与对话编辑更完整

- 完善玩家外交的续谈、回复归属和回应期限，减少文书或后续回复接错请求的情况。
- 修复口头外交在保密处理后丢失已谈妥执行资料的问题；正式执行仍需满足游戏规则，并避免重复执行。
- 外交系统的提交、发布等回执，不再混入 NPC 在信使、自由对话和场景交流中的正常发言。
- 可撤回并编辑最近一轮已完成的原生对话或场景对话，通过对话面板角落的图标进入。**编辑对话不会撤销已经发生的交易、关系变化或其他游戏动作。**
- 外交通知支持完整黄字显示；宣言长度作为写作建议，默认范围调整为 100～300。
- 完善赎金支付后的释放流程，让玩家按对话提示结束会话并继续游戏。
- 修复场景多人接力被打断后仍按旧计时判定超时的问题。对话空闲超时只会静默结束等待，不再新增“玩家长时间没有发言”的记录或让 NPC 因此产生冷落反应。

## 设置、界面与运行修复

- 终端设置修改后自动保存，并与 MCM 共用原生设置数据，减少重启后丢设置、两边读到不同配置的情况。
- 修复部分模型下拉框刷新与绑定问题，补全环境 AI 的连接测试入口。
- 调整终端战争信息列宽、部分字号与场景中的终端快捷键使用；修复 MCM API 分类中英文叠着显示，以及多个界面直接显示“\n\n”而没有换行的问题。
- 调整每日市场检查，避免同一天重复全图处理，并将一轮检查分散到不同帧。大型市场仍可能带来短时开销，不保证所有卡顿都已消除。
- 修复部分诊断日志和插画采集资源处理问题，减少额外开销与异常。
- 玩家向 NPC 给予俘虏时，只列出当前随身队伍中的俘虏，不再把家族地牢中的俘虏当成随身可交付对象。
- 加强长文本保存与读取完整性检查，补齐来信数据的分块保存；历史上下文只控制单次请求携带的旧事实数量，保留原始历史记录。

## 安装说明

- 提供 CN、EN 两种内容包；每份都只有一个 AnimusForge 模块，并包含 Bannerlord 1.3.x / 1.4.x 两种实现，由启动组件选择对应版本。
- 界面语言仍跟随游戏设置，固定提示词与世界书跟随内容包；内容包不会强制 AI 只使用某一种语言回复。
- ONNX 模型不包含在这两份更新包中，继续沿用原有独立模型文件。
- 发布前已完成双版本构建及相关离线回归。真实模型输出、长期旧档和第三方模组组合仍需游戏内验证；更新前建议保留自己的存档与自定义资料备份。
