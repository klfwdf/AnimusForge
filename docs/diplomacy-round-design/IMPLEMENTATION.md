# 多事件外交调度实现与验收

## 范围与所有权

本次只调整回合归属、开案名额、请求调度、公开知识可见时机及玩家等待提醒。原有多对象、多动作、协议条款、正式接受权限、效果执行、口头承诺及结束资格继续由既有实现负责。它不是整个外交模块化计划的完成声明。

`AF.Module.Diplomacy/Application/WorldDiplomacyOrchestration` 是回合、口头约定及调度的唯一业务 owner，使用 `WorldDiplomacyStateStore` 持有原存档；存档键仍为 `_af_world_diplomacy_v1`。`WorldDiplomacyOrchestration.Scheduling.cs`、`Dispatch.cs`、`Recovery.cs` 负责并存调度、请求租约及玩家回应承接。World Behavior 仅提供生命周期、实时身份、主线程游戏效果和传输适配，`DiplomacyRoundWorkRules` 提供对既有记录的确定性合并、来源覆盖及事件材料构造，`DiplomacyRequestBudget` 是唯一 HTTP 发送额度 owner。三类请求都使用原共享 gateway/client，不另建长期记忆或压缩器。

每个 NPC 最多自主发起一个活动普通事件，参加其他事件不限。玩家发文与 `dialogue_commitment` 特殊事件不占此名额。政策触发使用普通事件名额，不加入独立口头承诺事件。

## 共同交涉与恢复

2026-10-05 已按用户后续要求恢复距离传播和原接力顺序。公文发布只使作者及起点立即获知；其他王庭与民间按各自配置的到达日期获知，接力收件沿用原规则。玩家回应义务在送达前持久保留；送达后优先合并本国现有发言，额外优先回应不取消下一站、不消费接力游标，失败不推进原顺序。人物查询、口头原案资格及宣言请求中的公文/摘要/关联事实均服从实际知识范围。旧即时公开阶段已经保存的知识不删除。详见[交付说明与验证边界](UPDATE_20261005.md)。

玩家公文先照常公开，原解析请求追加当前公开交涉的定位材料；准确匹配则归入原事件，否则保留独立玩家事件。没有新增发布拦截或要求玩家澄清的入口。原案动作仍经过原有合法性验证。

来源公文 ID 与受案国组成回应身份。相关国家已有排队发言时合并成同一任务，实际发送前重建材料，读取同事件最新公文及本批玩家诉求。正文必须回应所选来源，结果另含 `answered_player_document_ids`；只有通过原发布验证的非玩家公文才能完成回应身份。技术回执、仅阅读、其他国家答复不完成该身份。模型正文是否真正自然接话仍需实际模型与游戏验收。

同事件最多一个发言生成在途，不同事件可并行。实际 HTTP 租约独立于待办列表，关闭事件或移除任务不会提前释放槽位。事件版本、请求尝试序号与运行代次约束晚到结果；无关事件的新历史不使当前事件发言失效。主线程串行应用效果并沿用既有世界状态复查。

连续发言保留全部待回复来源，单批最多六份、正文预算约 18,000 字符，超出部分留待下批；首份过长时仍保留并由既有输入预算保护处理。原回合按原规则关闭后，待回复身份转到引用原公文的玩家后续事件；不重发玩家公文，不复活过期协议。所有身份、归属、版本、预算和实时退避期限作为附加字段保存；旧存档首次恢复先确认已公开的已有回复，再补排待办。

## 预算、记忆与性能

当前工程默认同时最多三个请求，每游戏日总共十二次实际 HTTP 发送，非玩家最多八次，余下四次为玩家保留。普通、玩家、口头、压缩、重试及 thinking fallback 共用此银行；额度耗尽保留待办并提示。暂停不刷新额度，技术退避按实时计算。老的普通任务按游戏日等待增加调度权重，避免持续被优先事项压住。

固定 DECLARE/COMPACT 系统契约与共同历史缓存键保持原样，事件动态内容只进入末尾请求材料。回应来源写入同一公共历史并使用既有受保护 `response_link` 事实参与压缩。没有第二套压缩状态。并行本身不复制每日预算；增加事件、保证回应及失效重生成仍可能增加实际 token，缓存命中率需实际使用数据验证。

调度最多每秒尝试一次；回应重整只在任务/事件变化或日期变化后执行，到期接力每次最多八项。请求发送前才构造最新已知事件材料；额度检查在重建重型 prompt 之前。地理与距离在公文发布时捕获一次；每日传播只处理排序队列的到期前缀，服从原批量上限。人物查询使用原定居点/贵族/王庭知识，近期窗口的公文索引只增量处理新增材料，不逐帧扫描人物或全文历史。未公开的私人口头材料不进入公共知识。原五游戏日等待保留并补上剩余时间提醒。
