## 0. 已确认边界

```text
AnimusForge.dll 内部
├─ AF 主体：对话、LLM、Prompt、标签、记忆、调度
├─ 制作组内部模块接口与薄桥 → 政策、宴会、GCCZ 等
└─ 对外 API ← 独立子 MOD 的 DLL
```

- 制作组模块源码编入同一主 DLL；内部接口与子 MOD 公共 API 分开，底层主体管线共享。
- 我们处理主体与接缝，不重构政策、宴会、GCCZ 等业务、数值、状态机和业务存档，不重写独立子 MOD。
- 不改变 Bootstrap、单模块双实现及既有程序集/存档身份；没有将拆独立 Contracts DLL 作为本方案。
- 旧 20 **领域**清单只作影响面与兼容参考。本文 A/B/C/D 是新的主体工作编号，不是把全部领域重新实施。
- 英文代码、接口与稳定 ID；规则/玩家提示可以中文。具体签名、名称和首版开放能力仍待审。

## 3. 每项要改什么、怎样验收

“关联项”是设计/实施依赖，不表示审批必须捆绑；缺少依赖的审批或条件时不能偷偷实施依赖项，可先交付草案。C02 只依赖实际选择的渠道，不要求首版开放所有渠道。

### A01 · 主体功能基线与责任清单
- **决定：待确认；优先级：最高；关联项：无。**
- **现状：**已有多渠道入口、共享服务和旧功能；不能按文件夹或是否编进 DLL 判断主体范围。
- **拟做：**逐项登记原版输入/流式/主动开场、场景多人/接力/旁听、信件对话、Prompt/记忆/标签/展示的调用入口、状态 owner、接口责任、原行为和测试基线。
- **不做：**不新增玩法，不把政策/宴会/GCCZ、运输寻路及各业务存档列为我们要重写的模块。
- **验收：**每项原功能有归属、旧路径与对照用例；边界未定的基础交互单列，不默认删除或扩权。

### A02 · 请求、线程与 Gateway 服务接缝
- **决定：待确认；优先级：最高；关联项：A01。**
- **现状：**Snapshot、Coordinator、Gateway、取消/过期和提交守卫已有实现；渠道调度仍分散，同步 Action 网络目前只能拒收晚结果。
- **拟做：**复用现有服务，明确 prepare/network/complete 的线程和请求作用域；统一超时、重试、错误、取消及 provider 配置接缝，补齐需要的底层可取消调用。
- **不做：**不造第二套 Gateway，不改变模型配置/用户重试选择，不把同步网络搬主线程，不承诺撤销已开始副作用。
- **验收：**断网、取消、读档、目标替换和晚返回关联正确请求；主线程可响应；配置和凭据不因统一接口泄漏。

### A03 · Native 完整对话渠道适配
- **决定：待确认；优先级：高；关联项：A01/A02/A06/A07/A08。**
- **现状：**Native 保留旧默认完整入口，新 facade/opt-in 不是全部普通输入、流式和主动开场的默认替代。
- **拟做：**把普通输入、流式正文、主动开场与完成回调接到共同内部服务，保留权威上下文、后处理和展示顺序，形成可对照候选。
- **不做：**本项不切默认入口，不删除旧公开重载，不改会面/对话玩法。
- **验收：**对照流式顺序、主动开场、动作、历史和结束；主动开场不得伪造玩家发言。

### A04 · Scene 现有闭环收口
- **决定：待确认；优先级：高；关联项：A01/A02/A06/A07/A08。**
- **现状：**默认正文生成与完整场景后处理已分离，框选冻结、接力/旁听和旧回调隔离已有修复。
- **拟做：**将生成、权威后处理、动作/记忆和展示之间的接缝整理为渠道适配器，不改变闭环语义。
- **不做：**不重写成熟实现，不漏接力/旁听，不让正文标签直接执行，不改额外模块资格。
- **验收：**既有反例保持有效；受控回复下接力、旁听、动作与玩家发言记录均只发生应有次数。

### A05 · Courier 双向前置准备线程修复
- **决定：待确认；优先级：最高；关联项：A01/A02。**
- **现状：**信使正文和权威后处理已修；回信/主动来信更早的 builder 仍在后台混合游戏读取、aux、人设和历史/记忆准备。
- **拟做：**拆分主线程捕获、后台网络/纯计算、主线程完成；明确“已准备但为空”与“未准备”，保留完整消息和原规则。
- **不做：**不改运输、寻路和送达业务，不缩减记忆，不将整个 builder 搬到主线程同步等待。
- **验收：**双向游戏读写有线程见证；网络阻塞时 tick 可响应；空结果不重复请求，旧请求不写新 profile 或清新标记。

### A06 · Prompt、规则与上下文服务
- **决定：待确认；优先级：高；关联项：A01/A02。**
- **现状：**三阶段 Prompt、完整消息及 raw/visible 分离已有基础；模块贡献和人设/知识/记忆准备仍散布于旧 owner。
- **拟做：**明确各阶段输入、顺序、来源、缓存版本和预算；复用现有人设/知识/记忆能力，为内部模块提供贡献接点。
- **不做：**不改模块规则内容、资格或优先级，不重写 ONNX/RAG 算法，不强制所有渠道预算相同，不每轮注入全部模块。
- **验收：**逐条对照消息、顺序、规则命中、历史、预算及 raw/visible；动作格式不漏正文，没有无意重复前处理。

### A07 · 标签、ActionPlan 与执行协调
- **决定：待确认；优先级：最高；关联项：A01/A02。**
- **现状：**公共解析器、ActionPlan、权威归一化、回执和重复提交防护已存在，主体仍有具体模块动作分支。
- **拟做：**明确协议解码→领域权威归一化/资格→计划→执行前重验→执行回执的责任，为处理器登记预留统一调度接点。
- **不做：**不放开任意 raw 标签执行，不重写模块算法，不用通配符绕过授权，不承诺无条件全局 exactly-once。
- **验收：**未知、冲突、未授权、重复及过期动作不执行；合法动作只到一个权威 owner，部分成功/未知不盲目重试。

### A08 · 历史、记忆与 AFEF 唯一提交责任

- **拟做：**逐接缝指定正文、确认事实和延迟结果的唯一提交方；统一角色语义和恢复接入，桥接业务真正完成的回执。
- **不做：**不迁移模块业务状态机、不改 SyncData 键/类型，不开放任意写“确认事实”，不把排队或承诺当已发生。
- **验收：**正常、拒绝、接受/排队、实际执行、部分成功和未知结果的历史/AFEF 一致且不重复，跨读档行为有证据。

- **不做：**不重新设计 UI，不重写 TTS 引擎，不删除旧事件 ABI，不把提交音频当播放结束。
- **验收：**FIFO、取消重播、切场景/读档、口型/气泡/文字等待和结束通知不串轮；实际音频单列实机验证。

- **不做：**不造 DLL 扫描/下载器，不改变同 DLL 方式，不把必要安全补丁改为可选，不承诺中途卸载存档 owner。
- **验收：**重复登记、缺依赖、版本冲突、未激活均明确处理；无关模块不阻断普通对话；登记只做必要的一次解析/缓存。

- **不做：**不改模块提示语/玩法含义，不允许替换全局 Prompt，不把 GCCZ 规则带入普通场景。
- **验收：**未激活模块零注入；仅调用相关贡献者，保持原顺序与资格，同一轮不重复贡献。

- **验收：**每个获准接点对照原输入输出/副作用，未启用不串规则、AFEF 不双写；没有把业务实现搬到桥里。

- **不做：**不造另一套 LLM 管线，不默认开放无限制原始 AI 请求/任意动作执行，不改运输业务或直接切默认入口。
