AnimusForge 动作标签实际用途表
生成日期：2026-07-04
编码：UTF-8

范围说明：
本表按当前 animusforge-1.3.x 工作区整理，主要依据：
- AnimusForge/ModuleData/ActionPostprocessPrompts.json
- AnimusForge/ModuleData/RuleBehaviorPrompts.json
- RewardSystemBehavior.cs
- ShoutBehavior.cs
- LordEncounterBehavior.cs
- SceneTauntBehavior.cs
- VanillaIssueOfferBridge.cs
- WorldMapPartyCommandBehavior.cs
- DiplomacyBehavior.cs
- NobleGatheringBehavior.cs
- AnimusForge.SiegeAftermathIntervention/SiegeActionTagCatalog.cs

重要原则：
1. 主回复正文不应主动暴露这些标签；动作标签应由后处理链路输出。
2. 当前推荐标签以 ModuleData 规则表为准；C# 里仍保留的旧标签在本表末尾单独列出。
3. 情绪标签属于后处理强制标签，但不直接改变游戏机制，只影响后续情绪/状态判断。
4. 同一轮可输出多个大地图标签；STOP 仅可位于首位，改派时其后按新顺序继续输出任务标签。

一、通用情绪与全局后处理标签

| 标签 | 实际用途 | 触发条件 | 实际效果/注意 |
| --- | --- | --- | --- |
| [ACTION:MOOD:DELIGHTED] | 情绪：赞赏 | NPC 本轮回复明显赞赏玩家 | 后处理必须且只能输出一个情绪标签。 |
| [ACTION:MOOD:JOY] | 情绪：喜悦友好 | NPC 本轮回复友好、开心 | 不直接改变物品/关系机制，只作为情绪状态。 |
| [ACTION:MOOD:NEUTRAL] | 情绪：平淡 | 无明显情绪倾向 | 默认兜底标签。 |
| [ACTION:MOOD:BORED] | 情绪：抱怨/厌烦 | NPC 对玩家有所抱怨 | 不等同敌对。 |
| [ACTION:MOOD:ANNOYED] | 情绪：恼火/反感 | NPC 明显恼火、反感玩家 | 不自动开战；开战要用挑衅/战斗标签。 |
| [ACTION:NPC_SURRENDER] | NPC 或其军队投降 | NPC 明确同意缴械投降；围城语境下也用于当前方投降 | 在遭遇/场景/围城会话中触发投降处理，使目标成为俘虏或触发围城投降链路。 |
| [ACTION:KING_ABDICATE_TO_PLAYER] | 国王让位给玩家 | 当前 NPC 是国王，且明确同意把王位/统治权立即让给玩家 | 由 RewardSystemBehavior 执行王位转移；只支持 NPC 自己让位给玩家，不是封臣、领地或未来承诺。 |
| [ACTION:INTIMACY_INTERNAL] | 已发生性行为与内射事实 | 面对面对话本轮必须明确已经发生性行为，并且明确发生内射或男方在女方体内射精；玩家单方面明确叙述这些事实已发生也算；无需具体描写插入过程，但仅有亲吻、拥抱、抚摸、调情或暧昧亲密不够，避孕描述不触发 | 只对当前成年异性 Hero NPC 生效，信使禁用；左下角提示亲密行为，再按 MCM“15. 亲密行为与怀孕”的概率判定怀孕，默认 50%。标签不代表必定怀孕。 |

二、决斗标签

| 标签 | 实际用途 | 触发条件 | 实际效果/注意 |
| --- | --- | --- | --- |
| [ACTION:DUEL] | 发起正式决斗 | 玩家与 NPC 双方明确无条件同意单挑/决斗 | 进入决斗处理；普通吵架、叫嚣、群战、还在谈赌注时不应输出。 |
| [AD;金额;天数;备注内容] | 决斗赌注债务 | 与 [ACTION:DUEL] 同轮，玩家下注但未即时交付 | 决斗链路会把该债务延后到决斗结算后处理。 |
| [ACTION:DUEL_LINE_WIN:吹嘘的内容] | NPC 决斗胜利台词 | 输出 [ACTION:DUEL] 时配套输出 | DuelBehavior 缓存为 NPC 赢后嘲讽/吹嘘。 |
| [ACTION:DUEL_LINE_LOSE:吐槽的内容] | NPC 决斗失败台词 | 输出 [ACTION:DUEL] 时配套输出 | DuelBehavior 缓存为 NPC 输后吐槽。 |

三、交易、赠予、债务与资产转移

| 标签 | 实际用途 | 触发条件 | 实际效果/注意 |
| --- | --- | --- | --- |
| [ACTION:GIVE_GOLD:金额] | NPC 给玩家第纳尔 | NPC 明确把钱交给玩家 | 从 NPC/市场库存转移金币到玩家；数量不足时按实际可给数量处理。 |
| [ACTION:GIVE_ITEM:物品名称:数量] | NPC 给玩家物品 | NPC 明确交付其库存中存在的物品 | 从 NPC/市场库存转移物品到玩家；禁止填兵种和人名。 |
| [AD;金额;天数;N/P;备注内容] | 建立承诺/债务 | 一方承诺未来交付，或交易中一方先给、另一方未给 | 金额为承诺价值；天数为期限；N 表示 NPC 欠玩家，P 表示玩家欠 NPC。当前主要债务模型。 |
| [ADP;债务ID] | 债务解除/付款确认 | NPC 承认收到对应债务付款、豁免或结清 | 解除指定债务；代码也兼容 [ADP:债务ID]。 |
| [ATT:部队编号:数量] | 部队转移给玩家 | NPC 明确同意把当前编号清单中的部队交给玩家，或要人允许招募志愿兵 | 编号必须来自本轮清单，不能写兵种名；只用于士兵，不用于物品或同伴部队命令。 |
| [ATP:俘虏编号:数量] | 俘虏转移给玩家 | NPC 明确同意交出编号清单中的俘虏 | 编号必须来自本轮清单，不能写俘虏名。 |
| [ACTION:SETTLEMENT_TRANSFER:TO_PLAYER:固定资产ID或编号] | 固定资产转给玩家 | NPC 明确同意现在把城市、城堡、工坊、商队或商船队转给玩家 | 当前规则表只推荐 TO_PLAYER；代码层能识别 TO_NPC，但当前提示词明确不把“玩家给 NPC”走此标签。 |

四、势力身份、家族归附与王国关系

| 标签 | 实际用途 | 触发条件 | 实际效果/注意 |
| --- | --- | --- | --- |
| [ACTION:KINGDOM_SERVICE:LEAVE:current] | 玩家退出当前效力 | NPC 与玩家正式同意玩家退出当前雇佣兵/封臣身份 | 推荐格式；用于玩家本人退出，不用于 NPC 退出。 |
| [ACTION:KINGDOM_SERVICE:MERCENARY:{targetKingdomId}] | 玩家加入目标王国当雇佣兵 | NPC 与玩家正式同意玩家以雇佣兵身份加入目标王国 | targetKingdomId 必须来自运行时事实；不用于 NPC 加入。 |
| [ACTION:KINGDOM_SERVICE:VASSAL:{targetKingdomId}] | 玩家加入目标王国当封臣 | NPC 与玩家正式同意玩家以正式封臣身份加入目标王国 | 受家族等级、目标身份和权限约束。 |
| [ACTION:KINGDOM_SERVICE:CLAN_JOIN_PLAYER_KINGDOM:{targetClanId}] | NPC 家族归附玩家王国 | NPC 是目标家族族长，明确带整个家族加入玩家王国 | 会改变家族王国归属；其封地应随家族进入玩家王国；不代表 NPC 本人入队。 |
| [A:H_J_P_P] | 当前说话英雄本人加入玩家队伍 | NPC 明确同意本人立即加入玩家队伍/成为同伴 | 只代表当前说话者本人，不代表家族归附、封臣效力或大地图部队合并；俘虏/囚禁状态禁止用。 |
| [ACTION:KING_ABDICATE_TO_PLAYER] | 国王把王位让给玩家 | 国王明确无条件立即让位给玩家 | 见通用标签；放在此处也是王权机制。 |
| [ACTION:VASSALAGE:SUBMIT:TRIBUTARY:{kingdomId}] | 王国成为朝贡国 | NPC 国王明确同意交贡换保护但不出兵 | 保留目标王国存在；不是国家吞并。 |
| [ACTION:VASSALAGE:SUBMIT:GARRISON:{kingdomId}] | 王国成为卫戍国 | NPC 国王明确同意军事臣属、承担出兵义务但不纳贡 | 保留目标王国存在；没有军事自主权。 |
| [ACTION:VASSALAGE:SUBMIT:VASSAL:{kingdomId}] | 王国成为附庸/傀儡国 | NPC 国王明确同意外交军事受玩家王国控制并出钱出兵 | “附庸国”在当前规则中只对应 VASSAL。 |
| [ACTION:KINGDOM_ANNEX:target_kingdom_id={targetKingdomId}] | 国家吞并 | NPC 国王明确同意整个王国并入玩家王国，放弃独立王权，所有家族归入玩家王国 | 不用于朝贡、卫戍、附庸、保护国、求和或普通臣属。 |

十、大地图部队命令

| 标签 | 实际用途 | 触发条件 | 实际效果/注意 |
| --- | --- | --- | --- |
| [ACTION:WORLDMAP_ORDER:GO_TO_SETTLEMENT:settlement:{id}:{days}] | 命令 NPC 部队前往定居点并停留 | NPC 明确同意前往/守备某个候选定居点 | id 必须来自运行时候选；days 未指定通常填 3。 |
| [ACTION:WORLDMAP_ORDER:PATROL_SETTLEMENT:settlement:{id}:{days}] | 在定居点附近巡逻/游击 | NPC 明确同意前往某定居点附近巡逻 | id 必须来自候选；days 未指定通常填 3。 |
| [ACTION:WORLDMAP_ORDER:FOLLOW:{hero|party}:{id}:{days}] | 跟随英雄或部队 | NPC 明确同意跟随玩家、某英雄或某队伍 | 跟随玩家时目标类型用 hero，id 使用玩家固定 hero ID。 |
| [ACTION:WORLDMAP_ORDER:ATTACK:{hero|party|settlement}:{id}:{days}:{AI|FORCE}] | 攻击英雄、队伍或定居点 | NPC 明确同意攻击目标 | settlement 代表围城或掠村；AI 为谨慎评估，FORCE 只用于玩家明确要求强攻。 |
| [ACTION:WORLDMAP_ORDER:MERGE_TO_PLAYER:{days}] | 独立任务部队并入玩家主队 | NPC 明确同意把自己的独立部队并入玩家队伍 | 仅玩家家族独立部队或已登记的玩家主队拆出任务队伍可执行；不会自动补充。 |
| [ACTION:WORLDMAP_ORDER:STOP] | 清空当前大地图命令 | NPC 明确同意取消、停止或改派 | 必须是本轮首个世界地图标签；改派时其后继续输出新任务。 |

玩家主队 MemberRoster 中的非玩家 Hero 接受首个 GO/PATROL/FOLLOW/ATTACK 时会隐式打开一次分兵界面，无需建队标签。已有独立部队的新命令严格追加到旧清单末尾，包括追加到已有归队命令之后。

十六、常见排查要点

| 现象 | 优先检查 |
| --- | --- |
| NPC 正文答应了但游戏没触发 | 同一话题的 PostprocessRules 是否注入到 {tag_rules}，后处理是否实际输出标签。 |
| 后处理输出了标签但无效果 | C# 正则是否支持该格式，目标 ID/编号是否来自运行时清单。 |
| 债务没记录 | 当前推荐用 [AD;金额;天数;N/P;备注]，并确认方向 P/N；旧 DEBT_* 不应作为新规则依赖。 |
| 士兵/俘虏没转移 | ATT/ATP 必须使用本轮编号，不要写兵种名或俘虏名。 |
| 场景带路/传唤失败 | SCENE_GUIDE/SCENE_SUMMON 目标必须来自【带路与传唤NPC清单】，不要输出坐标。 |
| 攻城处置误触发 | 搜掠/血洗/殖民只能由玩家己方入城士兵直接回应玩家明确命令触发；平民侧只能局部抢钱。 |
| 大地图命令顺序异常 | 新 WORLDMAP_ORDER 默认追加旧清单末尾；明确取消或改派时先输出 STOP，再按新顺序输出任务。非首位 STOP 会被忽略。 |
