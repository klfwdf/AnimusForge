# AnimusForge 宣权篡位

当前主线已将 Coup 编入 `AnimusForge.dll`，由 `IntegratedModuleHost` 启动，只需启用统一的 AnimusForge 模块。MCM 仍保留独立设置页。下方独立子模组构建说明仅供维护旧输出；旧模块检测到主体接管后会跳过注册。

## 使用

- MCM 的“AnimusForge - 宣权篡位”可开关新政变，默认开启；关闭后已有事件仍收尾。
- MCM 另有“突击队”“守卫与增援”两组设置，全部无需重启、仅影响下一次发动。街道突击队默认60（1–120）、大厅突击队默认20（1–40）、门卫默认10（1–30）、大厅护卫默认20（1–40）；守军每波默认30（1–60）、间隔默认30秒（5–120）、同时存活波数默认4（1–4）。人数不含玩家或国王。每次发动会固定并保存这七项参数，转场、读档不受后续MCM调整影响。
- 玩家必须是本国正式封臣及家族族长，在本国国王实际停留的本国城镇发动“宣权篡位”；先退出军团及其他战斗/处置流程。默认还要求家族4级、影响力300，以及实际选中60名健康普通士兵，另留1名接应，因此至少需要61名健康普通士兵；玩家、英雄、伤兵不计入。影响力只检查、不扣除，不增加筹备、费用或等待。
- MCM“发动条件”可调最低家族等级4（0–6，0不限制）、最低影响力300（0–5000，0不限制）、最低突击队60（1–120）。最低人数超过街道上限会明确报配置冲突；默认上限也是60，因此默认必须选满60人。门槛在发动确认窗打开时固定，选兵前及确认时复核等级、影响力和实际名册。正式登记行动后不再追检这些门槛；大厅只需从幸存者中至少选1人。
- 选定突击队后，点击城镇菜单的“率领政变突击队攻入城镇”。SETS 按本次人数上限带入实际选中的士兵，并留一名接应。击败门口守军后到门口按 **F**，按本次大厅上限选择幸存者；返回城镇菜单点击“率领政变突击队攻入领主大厅”。两个专用入口按当前阶段显示，点击时重验国王、城镇与战斗状态。
- 护卫从真实健康守军分配，先大厅、再门口，其余留作街道守军；兵源不足不会补出额外士兵。两场景首波随战斗开始生成，后续按间隔和存活波数限制增援，兵源耗尽即停止。调整守卫上限改变分工，不改变真实守军总量；增大人数会增加场景负担及大厅拥堵。
- 大厅门使用原版交互键触发（默认 F），由政变接管实际 `PassageUsePoint.OnUse`：门卫未清除时提示阻止进入，清除后先结束街道并选兵，不会直接跳进普通大厅。政变内其他 location 门不能绕过转场流程；场景出口/退出战斗仍按撤退处理。普通场景门不受此限制。
- 制服国王并击败大厅护卫后，选择释放或扣押旧王。玩家取得原王国王位及本城，再按政变专用支持关系判定一次反叛：有起兵能力的旧王家族优先领导，其余家族只有对旧王关系高于对新王关系才反抗，不要求与新王关系为负。其余合格支持者作为跟随家族；关系相同或更支持新王者不加入。仍尊重叛乱总开关、玩家王国免疫、族长存活/成年/未被俘、拥有城镇或城堡等条件，不凭空制造候选人。起兵前复核原候选资格与支持关系；命名与建国继续使用AF原流程，普通每周叛乱规则不变。
- 王位、城镇、旧王处置与事实登记完成后自动打开原版胜利处置菜单，可继续选择 GCCZ 攻城处置；不会重复转移城镇。接口暂未就绪时保留完成状态，可在目标城镇点击“进入政变胜利处置”重试。菜单成功打开后保存收据，不因读档重复打开。战斗内仅提示本场守军击溃，不再误报当场按TAB必出普通SETS菜单。
- 倒地、撤退或放弃大厅进攻会失败：实际兵损保留，家族带原有封地脱离旧王国并开战。场景技术故障停止自动政治提交；部分结算可在城镇菜单重试。
- 扣押只阻止同阵营自动放人。主动释放、赎回、越狱、死亡及转出玩家保管仍沿原版处理。
- 成功或失败完成实际结算后，按快报开关登记专用“政变夺位／政变失败”事件：地点、王国、双方人物、突击队人数、实际街道／大厅进展、旧王处置及已记录伤亡。完整事实同时供快报写稿、无模型模板和 NPC 快报知识使用，沿用收集窗口与冷却，不强制弹报或额外请求模型。只有进场、突破门口等已确认阶段才写入；技术中断未结算不宣布成败。同一政变重试去重，旧已结算事件不追溯补发。

## 架构和兼容

政变反叛请求保存旧王/原王族标识及专用筛选标志；旧请求继续原判定规则，已经完成的旧请求不追溯重算。每次登记只遍历目标王国的家族，按原王族、对旧王相对支持差、封地数量、家族等级、稳定ID顺序选主导者，日志逐家族记录筛除原因。新增处置待处理/已打开标志沿原会话JSON保存；旧已完成政变不自动补开处置或补发反叛，需读夺位结算前的存档验证新流程。处置仅由完成结算的Coup owner发起，目标归属变化后取消过期入口；不复用战斗阶段SETS的普通占领队列。

发动门槛作为 `EntryRequirements` 保存在既有 `_afCoupSession_v1` 中，缺少新字段的旧会话使用0级/0影响力/1名突击队的历史规则；显式null或越界快照保留原JSON并拒绝继续。菜单按基础数值直接判断，不创建快照对象；健康兵力单次遍历本队名册、不扫描世界部队。新门槛不改变旧战斗、政治结算、快报或记忆语义。

本子模组持有政变目标、状态和存档。街道与大厅的进场、随行生成、编队、守军波次和指挥交给已安装 AF 的 SETS。政变只登记本次进城、判定国王与大厅门口，并在胜利后执行王位、归属和叛乱。它不改 SETS 的日常随行存档，也不走 SETS 的占领菜单。

这些接缝不是 AF 公共 API V1 的兼容承诺。SETS 不可用时关闭发动入口并记录原因。菜单结算由实时引擎 tick 驱动，避免城镇暂停时卡住。退出与读档后不保留 Agent 引用。政治执行仍在游戏主线程。

战斗参数由 Coup 会话持有，MCM 只在发动时读取并限幅。缺少 `BattleOptions` 的旧会话恢复历史60/20/10/20、30人/30秒/4波；显式空、缺项或越界的已存快照保留原JSON并拒绝继续。真实 Newtonsoft 对该字段使用替换语义，防止不完整快照被默认对象掩盖。主体 `QueueArmedCoupEntryWithOptions` 传递本次人数和波次值，旧四参数入口继续使用历史默认；普通SETS不读取政变配置。Mission缓存数值并沿用现有分批生成和增援调度，无新增轮询或每帧设置读取。

入口与叛乱调度的忙碌状态通过主体的 `HasBlockingFlowForCoup` / `HasBlockingRebellionFlowForCoup` 查询，启动时绑定并缓存 delegate，不依赖主体私有字段布局。菜单重算和已有引擎调度仅作 O(1) 状态判断；缺失接口或 SETS 查询异常仍关闭入口。统一主线使用仓库 `scripts/build/build_single_module.ps1` 构建两版和 Bootstrap，未授权时不添加 `-Deploy`。

场景挂载在 SETS 的 `OnMissionStarted` 完成后补通知，不依赖 Campaign 事件的注册顺序；重复通知仅附加一次政变 owner。兵员 Origin 的非公开构造器及伤亡回调在启动时验证，Origin 创建失败不允许以空 Origin 继续生成政变兵员。每场事件只作一次挂载检查，构造器仅首次解析；普通场景和原版伤害逻辑保持原路由。

`Guards registered` 启动日志里的 `captivity=False` 还可能表示战役拘押行为尚未构造；它不是单独的补丁失败证据。需结合 `Automatic detention protection unavailable` 错误与战役生命周期验证判断。

两版从同一源码编译，分别位于 `artifacts/1.3` 与 `artifacts/1.4`。部署只放与当前游戏匹配的一个实现；不把两份实现同时声明到启动器。当前双构建脚本需要 1.4 游戏安装，1.3 编译使用固定的完整 `Bannerlord.ReferenceAssemblies 1.3.15.110062` 引用包。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\extensions\AnimusForge.Coup\build.ps1 -BannerlordRoot '<游戏目录>'
# 用户授权覆盖后，显式添加 -Deploy；脚本只写 Modules/AnimusForge_Coup。
dotnet run --project .\extensions\AnimusForge.Coup\tests\Coup.ContractTests\Coup.ContractTests.csproj -c Release
```

构建不重编 AF；部署前备份同名模块，逐文件核对哈希，并检查原 AF 两个实现的哈希未变。`artifacts/deployment.json` 记录本机部署路径、版本及备份。

## 验证边界与回滚

离线状态/伤亡契约、两版编译与 DLL 成员核查不能代替实际场景验收。各文化城镇门口/大厅导航、真实指挥 UI、60 人街战性能、原生 Harmony 实际挂载及旧存档读写需要在游戏中验证。日志位于 AF 的 `Logs/Mod_Logic.txt`，检索 `[Coup]`。

MCM实际显示、120人街道突击队与40人大厅突击队的导航/性能仍需实机验证。回退旧程序时，超过旧人数上限的新政变存档不保证能被旧版读取；应使用发动前的存档。

尚未开始政变时可在启动器取消勾选本模块。进行中的事件应先收尾，再停用；已经发生的兵损、王权和领地变化属于存档内容，卸载 DLL 不会撤销。部署备份可恢复旧模块文件；战役结果回滚使用发动前的存档。
