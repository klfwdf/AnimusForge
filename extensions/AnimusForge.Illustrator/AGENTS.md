# Illustrator 持久维护规则

遵循仓库根 AGENTS.md。颜色修改前必须先读 `docs/color-channel-contract.md`。

## 不得再次引入的颜色错误（2026-09-17 实机反例）

- 已编码 PNG/JPEG 不等于原始 BGRA 显存。`Bitmap.LockBits(Format32bppArgb)` 的内存字节次序，不证明 `Texture.CreateFromMemory(encodedBytes)` 会交换红蓝。
- UI 的 `GauntletTextureLoader.PrepareEncodedImageForUi` 必须保持正常 PNG 的字节/像素；禁止恢复 `SwapRedAndBlueInPng` 或换名的等价转换。产品未发布：彻底删除 `FixColorChannels` 设置、options 字段及 loader 参数，不保留旧配置兼容层，不得仅隐藏开关或改默认值。编码颜色必须是无配置、无调用方覆盖入口的固定契约。
- 图像问题先按同一图像身份对比：原生导出→发送的参考图→服务端/缓存原图→游戏截图。不得仅凭“蓝皮”就改所有通道，不得按肤色统计自动猜测 RGB/BGR。
- 原生导出适配只作用于其已取证的生产者；修改须提供对应导出色块/实际旗帜对照。不得将该适配重复施加到标准缓存、HTTP 结果或 UI 加载。
- 保留红、蓝、金色、肤色、紫色及半透明色块的精确 RGBA 回归；首次加载与缓存重开都要测；反射与全源码扫描必须证明设置、options、修色参数和 PNG 交换函数不存在，实际 UI 加载入口必须调用被测试的准备函数。
- 当前用户图的缓存原色正常，UI 交换错误；不得通过删除缓存或要求付费重绘掩盖显示层缺陷。
- 离线颜色字节测试不能冒充 GPU 实机验收。部署后仍需重启游戏、重新打开旧缓存卡片对照。

## 装备、旗帜与姿态（同日拉盖娅反例）

- 必须保留完整 12 槽快照；`ItemTypeEnum.Banner` 单独记录，不得回落为普通手持武器。装备持有不等于现场可见或必须入画。**例外（2026-09-18 用户指定）：百科肖像在装备快照阶段即清空全部武器槽**（武器、盾牌、旗帜均不入画），事实区与离屏立绘同步无武器——装甲服饰保留；此清空仅作用于百科链路，会话/周报仍用完整快照。
- 百科是人物肖像，不是旗帜展示。不得把国王/家族归属、旗帜栏或纹章标准图当成举旗、挂旗的依据；实际盾面/服饰纹章仍须保真。
- 百科姿态与构图由导演自主推导。**2026-09-18 用户要求修复怪姿势与 Edits 抠图换背景，覆盖此前强制反站姿/每次换姿势规则**：自然可信优先，允许站立、坐姿或延续合理体态；重绘优先通过镜头、取景、光线或场景层次形成变化，不能强迫跨坐、踮脚、扭腰或多支点撑扶。参考图锁定身份与实际穿戴，不锁定原图像素、光照和轮廓；导演须说明机位、朝向和受光，生图端须将人物和环境统一重新绘制，而非只换背景。坐靠须有真实支撑。Chat 与 Edits 均需收到整幅重绘及参考图用途说明；不得把全透明 mask 视为“仅参考身份”的保证或自动附加该 mask。仅人物身份、装备、纹章等事实保持锁定，不编造不存在的装备。
- 百科专用限制不能全局删除会话/周报里有现场或事件证据的旗帜。
- 文本规则和拒绝回退不能冒充模型最终图像验收。显示层颜色修复不需要重绘；旧图片本身的动作内容需要用户主动重新生成才会改变。

## 行动优先与作品命名（2026-09-18 后续用户要求）

- 导演先决定人物此刻正在做什么，再推导姿态、手部动作、视线及镜头。保留自然站姿，但不能默认双手下垂展示装备；不强迫复杂动作。此条覆盖上文优先只换镜头/光线的重绘指导。
- 重绘读取同存档、同人物或同事件最近三张的行动摘要；百科减少重复展示姿势，会话/周报不能为去重改变当前事实。旧缓存可从人物与镜头段提取参考，历史行动不能当作现场事实。
- 导演同时给出标题与主题，单独保存和展示，不混入生图正文或当作画中文字。负面词只保留简短通用缺陷及选定画风所需排除词，不全局禁止露脸或添加面具专用限制。

## 画风与须发保真（2026-09-19）

- 古典油画预设统一维护：导演读具体的完整画法，生图端只追加简短画风要求；本地回退同样使用短版，不把导演说明整段重复给生图。用户已保存的自定义文本不得自动覆盖。
- 发色参数是种族色板中的偏移，不是通用金/棕/黑色编码；不得由色值、年龄、性别、文化或身份推断卷发、披发、盘发、胡须样式、白发。须发有无及可见形状以对应人物原始参考为准，装备遮发/遮须标记分别保留；秃头、无须、非人类不能套通用人类模板。
- 普通 NPC 的未知年龄不得硬填 28 岁或套壮年战士体格。参考图不足以辨认的细节保持未知，不让上一张生成图成为新的外观事实。

## 最新盾牌规则（2026-09-17，覆盖此前保盾兜底）

用户明确要求减少盾牌，背负也不要：百科默认不画任何盾牌；所有模式禁止背盾、露出背后或肩后的盾轮廓。其他场景只允许有明确实际持盾动作依据的从属盾牌，不把省略的盾变成背景陈设。完整装备仍读取并保留，不可通过删除快照槽来实现；禁止恢复“无持握证据则自然背负”。本条优先于历史交付文档里较早的保盾描述。

## 场景优先与近景半身（2026-09-17 最新追加）

- 2026-09-18 用户要求多视角还原环境：会话参考图须保留完整画面（不再只截上半部），可在原 Mission 拍摄点原地获取四向环境视图，只发送给导演。不得新建手动 tick 的 Scene/TableauView；采集后及取消/切场景时恢复相机与隐藏界面，不抢占其他系统的自定义相机。不满足采集条件时使用实际取得的视图，不能把重复截图标为全景。导演保留现场墙面材质配色、楼梯门窗位置、层高和陈设关系，不能依据地点名称重造环境。
- **2026-09-19 用户实机反馈覆盖前条的可见采集方案**：不得接管或旋转玩家相机，也不以隐藏界面、遮罩冻结画面来掩盖转镜。使用独立相机及离屏 SceneView/渲染目标借用现有 Mission 场景；不新建或手动 tick 场景，不修改共享场景的光照/曝光，清理只作用于自有 view，严禁清空 Mission 场景。失败时保留已取得的视图，不退回可见转镜。GPU 开销、原生导出及退出仍须实机验收。
- **同日后续场景不还原反馈**：多向现场图继续全部供导演识图，另外选择一张已取得的真实现场图交给生图端（用户关闭生图参考图时仍尊重开关），防止环境仅凭文字转述。标签明确保留空间布局、材质、固有色及高低关系，按导演画法重绘，不粘贴截图/UI。此条覆盖更早“场景图只发导演”的限制。

## 五项优化（2026-09-19 用户确认全部实施）

- 人物使用同一 Appearance/Equipment 的全身与原生头肩近景。头肩图是同名人物细节，不增加人物数量，不脱头盔、不恢复被游戏隐藏的头发；头像失败保留全身，取消仍传播。不能把低清全身裁剪放大称为新增原生细节。
- 百科先判断实际穿戴装甲槽的纹章载体，再决定是否原生导出并发送纹章图；家族旗帜归属不等于可见载体。会话/周报现场旗帜与其他明确载体不受百科专用过滤影响。
- 导演的结束标记、截断、识图不支持和本地回退独立记录/显示，不混入生图正文；截断或无效回复不自动付费重试。
- 每次生成记录实际请求文字、模型、参考图身份与有限份原图、返回状态、耗时和执行程序集标识。诊断按数量/容量限额保留，不记录密钥；诊断失败不能阻断生成。使用诊断文件与日志判断真实链路，不以“原生导出完成”推断模型收到图片。
- 缓存索引按存档/分类/对象隔离；画廊文件读取与解码在后台，纹理注册留主线程，快切与关闭丢弃晚结果。优化不能绕过固定颜色契约，也不能把所有原图常驻显存。

## 预制体全景与无感知采集（2026-09-19 实机纠正，覆盖上文旧方案）

- 用户要的是后台多个镜头导出并合成为全景，以实际预制体、材质、摆放和装饰还原环境，兼容第三方场景；单张屏幕截图不能替代这个目标。
- `1c92decf` 的实机诊断已证明借用 Mission.Scene 的副 SceneView 产出重复角度、人物破面和蓝色原始参考。不能再用“没设置 CombatCamera”证明主画面没有副作用，也不能用相机矩阵数学测试冒充实际六面采集成功。
- 六面相机只渲染由实际现场实体复制的独立冻结环境 Scene。禁止重新按 prefab 名称或文化模板搭景，禁止直接复制真实 Agent 骨骼；源/目标 Scene 和实体指针必须分离，禁用副本物理、脚本回调及布料模拟，不能手动 Tick Scene。使用原版引擎 PaintNeeded 调度，每方向实际重新提交 Camera。
- 全景应是六面投影成一张 360×180 环境参考，不是六图拼贴；重复六面/缺面/超预算必须明确失败，不发送假全景。附加当前画面只校验颜色、采光和人物关系；截图副本可遮除 AI 面板，禁止实际隐藏或移动玩家UI。
- 当前实体快照不含原生地形、水面、真实人物骨骼和完整实时光照。中性观察光仅用于识别预制体网格/装饰/材质图案，不能伪称现场光照；第三方普通实体沿原生实际实例复制，未覆盖内容必须写入标签和诊断。
- 只有本次已取证的原生场景导出 PNG 在全景合成入口做一次 R/B 适配；正常编码图片、被动截图、UI加载和人物参考不增加换色。
- 性能：只在用户生成时采集；单次根枚举、分帧线性选择，最多8次原生复制/批、4ms软预算，明确数量和总时长上限。6相机顺序共用512方形RT，导出后关闭持续渲染，2048×1024投影在后台。单个native调用不可抢占，不得声称零帧率影响；保留采集/复制/帧间隔诊断。
- 人物导出控件保留provider生命周期但禁止提交屏幕Draw，不再依赖AlphaFactor或2像素裁剪来承诺完全不可见。

## 全景原生崩溃收窄（2026-09-19 06:07 实机反例）

- 大厅和酒馆在 `TaleWorlds.Native.dll + 0x461a0b` 相同位置读取空指针；首面导出前崩溃。不得用旧版离线通过数字声称修复后的GPU链路已验收。
- 全景副本禁止整棵 `GameEntity.CopyFrom`：该接口可能连源灯光、阴影及其他原生运行状态一起带入。仅复制可见静态 `MetaMesh` 的材质/局部帧，按源实体冻结的全局帧，用原版 `Scene.AddItemEntity` 挂载；不复制灯光、物理、粒子、脚本或骨骼组件，含布料模拟的分支也跳过。
- 自有Scene按原版Tableau建立必要基础设施（包括初始化独立的内部物理世界，但不复制源物理组件），使用中性观察气氛，关闭静态阴影与天空绘制；保留导出需要的自有postfx/focused shadow初始化。源场景参数不得更改。
- 每个源实体的多网格使用同一个冻结全局帧；按网格计数执行8次/4ms软预算，确认包围盒、可见性及网格/实体所有权。关闭时已退休的snapshot也能解除后台等待，不能依赖停止tick后的队列回调。
- 当前用户要求修复和代码审查、不跑离线测试；本轮用真实日志/转储、原版调用对照和双版本编译验证，并明确实机仍待复测。

## 原生渲染名称长度（2026-09-19 06:49 转储确证）

- 最新崩溃是 `ucrtbase.dll/_invoke_watson`，异常 `0xc0000409`、fast-fail参数5。Native `+0xd7936` 调 `strcpy_s`，目标容量128字节，走ERANGE失败分支。
- 转储中实际GBuffer标签含同一56字节 `af_environment_snapshot_<GUID>` 两次；`gbuffer_normals(2)` 加两次名称为130字节，已超过含终止符的128字节空间。不要再将这一轮当作旧空指针或以调整阴影参数规避。
- 本模块传给native的Scene/Tableau/RenderTarget标识必须短ASCII、至多16字节，使用进程内递增编号；完整GUID只用于诊断和文件路径，不能放进原生渲染名字。必须在调用native前检查长度，并记录实际短名称。

- 范围外节点仍可有范围内子节点，不凭父节点原点或未确认包含子树的包围盒剪枝；只把范围内候选加入复制队列。无效边界明确省略并记录。渲染远裁面和聚焦阴影范围同步收窄到附近范围，保留原分帧/数量/超时预算。
