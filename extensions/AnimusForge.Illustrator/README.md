# AnimusForge.Illustrator — AI 画卷动态立绘与史诗插画系统

`AnimusForge.Illustrator` 是专为《骑马与砍杀2：霸主》（Mount & Blade II: Bannerlord）打造的高性能 AI 动态插画与角色立绘子模组。

本系统深度集成在 AnimusForge 框架生态中，依托底层游戏引擎数据提取能力与现代生成式 AI（OpenAI 兼容生图 API / 多模态视觉大模型），为游戏中的每一位英雄、每一场重大会面、每一期国家周报与每一次风云变幻，实时生成具有古典写实油画（Rembrandt & Craig Mullins 质感）的史诗级纪事画卷。

## 一、 核心功能与技术特色

1. **全量游戏底层视觉感知（零硬编码）**：
   - 拒绝死板预设。全面动态读取英雄的所属文化官方传记、王国与家族历史、五大性格心理特质（算度、正直、胆识、宽厚、仁慈）、顶尖专长（战神、神射手、医师、智囊等）。
   - 提取角色精确的 FaceGen 骨相参数、发型、真实发色渐变索引、岁月斑白痕迹、胡须形态与自然人类微血管血色肤质。
   - **人物当前处境状态**：俘虏（区分定居点地牢关押/队伍锁链押送，附带武器收缴与简朴装束约束）、负伤、留驻下榻、随军扎营、已故纪念语境——画面不会把阶下囚画成自由旅行的全装骑士。
   - 提取家族徽记图腾（双头鹰、黑狼、雄狮等）与识别色，通过 HSV 颜色空间高精度映射为直观颜色（如“高贵淡雅的丁香紫”、“辉煌灿金/琥珀金橙”）。
   - 逐槽位（头盔/身甲/肩甲披风/手甲/腿甲/武器/盾牌/坐骑）提取真实穿戴装备与物理材质（黄铜札甲、锁子甲、织锦锦袍、兽皮大氅）。

2. **全息场景感知（宿主快照联动）**：
   - 联动主模组 `ShoutUtils.GetCurrentSceneDescription()` 场景快照，与本地判定交叉纠错——贴着城镇的野外遭遇不会再被误画成市集街道。
   - 场景覆盖：城镇子场景（街道/酒馆/地牢/港口/竞技场/领主大厅）、开阔野外（平原/森林/山地/海岸）、海上战船甲板、军团联营、围城阵前谈判、囚禁看押现场。
   - 非英雄会话方（劫匪等随机 NPC）使用在场 Agent 的真实体型面容渲染立绘，而非模板随机脸。

3. **原生 3D 角色模型离屏渲染（GPU 纯净垫图）**：
   - 突破传统屏幕视口截图容易混入 UI 杂质与背景遮挡的缺陷。
   - 深度调用引擎底层 `TableauView` 异步落盘管线，直接从 GPU 渲染通道抓取 100% 纯净且无任何 UI 遮挡的 3D 角色模型，作为送入视觉大模型（Vision LLM）的高清垫图。

4. **DirectX 11 色彩通道自动校准**：
   - 独家解决骑砍原生 DirectX 离屏 RenderTarget 导出的 **BGRA 像素通道翻转** 问题。
   - 内存级快速互换红蓝通道，彻底根除“阿凡达蓝皮”、“黄色刺绣滚边被误画成蓝色”、“金色盾牌老鹰画成蓝鹰”等严重色彩偏差。

5. **纯正中文古典写实油画提示词总监**：
   - 视觉导演引擎全面采用**纯正中文输出**，专为支持中文语义的现代主流生图模型（FLUX、Midjourney、DALL-E 3、可灵、SDXL 等）打造。
   - 具备“多模态视觉扩写（Vision LLM）”与“离线智能规则导演”双引擎机制，即便断网或大模型未开也能稳定组装高水准艺术提示词。
   - **台词只给导演不进生图**：当前台词与最近三轮对话历史仅发送给导演 LLM 用于提炼动作/情绪/构图，生图模型只收到视觉化后的提示词——画面不会再出现字幕或台词文字（生图尾部附禁文字硬约束）。

6. **全交互式 Gauntlet UI 视窗**：
   - 自由拖拽、缩放、立绘重绘、多图画廊浏览、一键设为默认立绘、查看生成提示词详情。

## 二、 安装与部署指南

### 1. 运行依赖
- 《Mount & Blade II: Bannerlord》v1.3.x / v1.4.x（本仓库已分别验证 `BannerlordApi=1.3` 与 `BannerlordApi=1.4` 编译；其他版本需另行实测）
- `Bannerlord.Harmony` (v2.2.2+)
- `Bannerlord.MCM` (Mod Configuration Menu v5+)
- `AnimusForge` (本体模组)

### 2. 构建、校验与热部署
- **1.4 构建**：
  ```powershell
  dotnet build extensions/AnimusForge.Illustrator/src/AnimusForge.Illustrator.csproj -c Release -p:BannerlordApi=1.4
  ```
- **1.3 兼容性构建**（使用固定的 `Bannerlord.ReferenceAssemblies 1.3.15.110062`）：
  ```powershell
  dotnet build extensions/AnimusForge.Illustrator/src/AnimusForge.Illustrator.csproj -c Release -p:BannerlordApi=1.3
  ```
- **只校验、不部署**：
  ```powershell
  .\tools\deploy_illustrator.ps1 -ValidateOnly -BannerlordApi 1.4
  ```
- **显式部署到当前游戏目录**（会先编译、校验模块清单和 prefab，并备份目标模块已有文件）：
  ```powershell
  .\tools\deploy_illustrator.ps1 -BannerlordApi auto
  ```
  输出位置为 `Modules/AnimusForge_Illustrator/`；该脚本不会复制 TaleWorlds、Harmony、MCM 或 AnimusForge 本体 DLL。

## 三、 MCM 配置详细说明

进入游戏主菜单或暂停菜单中的 **Mod 选项 (Mod Configuration Menu)**，找到 **`AnimusForge - AI 画卷生图系统 (Illustrator)`**：

### 1. 基础设置
* **启用 AI 画卷生图系统**（默认：`开`）：全局总开关。
* **启用多模态视觉提词 (方案 A)**（默认：`开`）：
  - 开启后自动抓取游戏内 3D 角色模型离屏贴图，传递给视觉大模型（如 GPT-4o、SWE-2、Qwen-VL）提炼精准提示词。
  - 若所配大模型不支持视觉，系统会自动平滑回退为纯文本高精度提词。
* **启用原生 3D 模型离屏渲染**（默认：`开`）：
  - 开启后通过 `TableauView` 直接从 GPU 导出无背景干净角色模型。
* **生成完成后自动清理临时文件**（默认：`关`）：
  - 开启后每个提取任务结束（无论成败）仅清理自身的离屏立绘和完整纹章 PNG，不清理其他请求或历史文件。
  - 不影响画廊缓存与默认插图；默认关闭以便排查问题，介意临时文件占用时开启。

### 2. 生图 API 配置 (OpenAI 兼容)
* **生图 API 端点地址 (Base URL)**：
  - 填写任何兼容 OpenAI 规范的 API 端点。
  - 常见平台示例：
    - 硅基流动：`https://api.siliconflow.cn/v1`
    - OpenAI 官方：`https://api.openai.com/v1`
    - 自建中转 / OneAPI / NewAPI：`https://your-api-domain.com/v1`
* **使用完整调用 URL (不自动拼接后缀)**（默认：`关`）：
  - 若你的中转平台需要直接访问特定路径，可开启此项。
* **生图 API 密钥 (API Key)**：
  - 填入你的对应服务商 API Key（如 `sk-xxxx`）。
* **拉取生图模型列表**（按钮）：
  - 点击后系统会向配置的 Base URL 发送请求，自动获取服务商支持的全部模型，并自动筛选出图像与绘画模型。
* **选择生图模型 (下拉选单)**：
  - 点选上面拉取到的可用模型；若选“\*手动输入\*”，则生效下方文本框填写的模型名称。
* **生图模型名称 (Model)**：
  - 手动填写的模型名称。例如 `black-forest-labs/FLUX.1-schnell`、`dall-e-3` 等。
* **生图分辨率尺寸 (Size)**：
  - 建议设置为 `1024x1024`（正方形肖像）、`1280x720`（横屏史诗场景）等。
  - 下方 **分辨率快捷预设** 下拉可一键写入常用画幅（含 1344x768 史诗宽画幅）；多模态模型自动换算为 1:1 / 16:9 / 3:4 比例。
* **生成画质预设 (Quality)**：
  - `standard/hd` 对应 DALL-E 3 系；`low/medium/high/auto` 对应 gpt-image 系；选"默认"不发送该参数避免报错。
* **生成风格画风 (Style)**：7 项预设——
  - `古典油画`（默认，伦勃朗/穆林斯式明暗对照）；
  - `vivid` / `natural`（OpenAI 官方 style 枚举，作为 API 参数发送）；
  - `暗黑史诗写实` / `电影级光影` / `莫桑艺术·默兹河珐琅彩饰`（作为画风指令+预设负面词注入提示词，对任何模型生效）；
  - `提示词`（自定义画风）：搭配下方"自定义画风提示词"编辑器自由编写。
* **自定义画风提示词**（按钮，`Style=提示词` 时生效）：大文本编辑器自由编辑画风指令，预填古典油画内容供改写。
* **向生图模型附带参考图 (垫图/图生图)**（默认：`开`）：
  - 开启后，人物 3D 立绘、家族纹章与现场实景参考图会随提示词一起发送给生图模型（仅对话多模态生图通道生效，如 Gemini Image 系列）。
  - 每张参考图都带有中文标签（如"对话对方一方【X家族】纹章""人物3D形象"）；纹章仅作一致性约束，不会强行给每张图塞盾旗。
* **负面提示词 (Negative Prompt)**（按钮编辑器，`Style=提示词` 时生效）：
  - 填写不希望出现在画面中的元素（如"模糊, 多余手指, 现代物品"），追加在预设负面词之后；预填古典油画负面词供改写。
* **随机**（0–100，默认 `0`）：
  - 0 沿用没有此设置时的旧版行为，不追加随机提示词；旧版已有的随机构图仍照常生效。
  - 数值越高，越鼓励取景、留白、景深和光影表现的变化；100 表示在事实允许范围内最大程度探索变化。
  - 人物外貌、装备、纹章、已确认游戏事实与场景空间关系仍须保留，不允许凭空增加物体。
  - 这是提示词指导强度，不是模型采样参数或出图差异百分比。旧相似度配置不转换为随机强度，新项默认 0。

### 3. 周报与展示场景
* **周报自动生成纪事插画**（默认：`开`）：每周国家周报弹出时自动绘制头条事件插画。
* **英雄百科页注入【纪事插画】按钮**（默认：`开`）：百科角色页面右上角显示插画按钮。
* **现场对话界面注入【场景插画】按钮**（默认：`开`）：对话会面时右上角显示场景插画按钮。

### 4. 存储与性能
* **本地缓存最大保留张数**（默认：`200` 张）：超过后系统自动清理最早的图片，防止硬盘占用过大。
* **修正 UI 显示色彩通道 (修复游戏内红蓝反色/蓝皮)**（默认：`开`）：
  - 极为关键。骑砍 2 原生 Gauntlet UI 着色器在采样 `CreateFromMemory` 创建的内存动态贴图时默认红蓝反置。开启此项会在装载进显存前自动校准为正常肉色与真实服饰。默认始终开启。

## 四、 游戏内四大核心展示场景

```
┌────────────────────────────────────────────────────────┐
│             AnimusForge.Illustrator 四大场景            │
├─────────────────┬──────────────────┬───────────────────┤
│ 1. 英雄百科肖像 │ 2. 现场会面对话  │ 3. 每周纪事周报   │
│   · 3D 离屏模型 │   · 双方对峙站位 │   · 军国大事件    │
│   · 家族服饰徽章│   · 场景环境感知 │   · 史诗历史画卷  │
├─────────────────┴──────────────────┴───────────────────┤
│ 4. 卡拉迪亚纪事画廊 (大地图营地菜单 Camp Menu 常驻入口) │
└────────────────────────────────────────────────────────┘
```

### 1. 英雄百科页面（人物专属立绘肖像）
- 打开游戏内百科（快捷键 `N`），点击任意一位英雄（如伊拉、拉盖娅、阿萨利格等）。
- 页面右上角会出现 **【查看立绘】 / 【生成立绘】** 按钮。
- 点击后弹出一个可拖动、可从右下角缩放的精致卡片：
  - 实时显示当前存档缓存中的默认肖像；没有缓存时才发起新的 AI 生成；
  - 底部提供 **【重新绘制】**（每次产出不同构图，重绘时导演会刻意换景别/机位/瞬间）、**【提示词】**、**【复制】**、**【纪事画廊】** 与 **【关闭】**；
  - 在画廊中选择任一历史版本并点击 **【设为默认】**，之后百科卡片会优先显示该版本。

### 2. 现场面对面对话（场景会晤插画）
- 在场景中与领主交谈、大地图遭遇谈判、围城阵前对话、海上接舷或地牢探监时，界面右上角会出现 **【场景插画】** 按钮。
- 系统抓取多张参考图：会面现场 3D 实景（自动剔除对话 UI 条带）、对方真实 3D 模型立绘（劫匪等随机 NPC 用当场 Agent 的真实体型面容）、**双方各自家族**的真实纹章旗帜。
- 当前台词与**最近三轮对话**只发给导演 LLM 提炼情绪与动作瞬间——生图模型看不到台词原文，画面不会渲染出字幕文字。
- 双方骑乘/站立组合会被精确还原（如玩家骑马居高、对方步行仰视，或双方并辔骑谈），对方随行护卫数量也会写入画面。
- 系统实时感知**场景物理空间与处境**：
  - 是领主大厅、酒馆、竞技场、港口、地牢，还是旷野/森林/海上/军团联营？
  - 当前定居点是否被大军围困？对话方是否是被锁链看押的战俘？
  - 附近有多少名卫兵在警惕巡哨？周围有哪些陈设道具与火把光影？
  - 根据上述全息数据，生成一张富有临场感的双方对峙/会晤油画。

### 3. 每周国家纪事周报（历史大事件油画）
- 依托 AnimusForge 本体的周报系统，当每周结算卡拉迪亚大陆发生的围城、宣战、政变等重大事件时，周报弹窗会自动嵌入一张根据头条战局生成的史诗风云画卷。
- 系统会从周报正文中**自动解析真正的当事人英雄**（而非默认玩家角色），优先取文本中最先被提及的君主/宗族首领，并用其真实的文化、性别、装备、家族纹章来绘制人物。
- **10 类事件主题**自动锁定场景：村庄劫掠→燃烧村落、野战→旷野军阵、围城→云梯投石机、庆典比武→宴会竞技场、外交→议事厅大帐、海战→接舷跳帮、囚禁处决→地牢行刑台、定居点易主→城头换旗、亡故继位→灵堂朝拜、通用→场景名词兜底（要闻出现渡口/军营/神殿等场所词时直接锚定，否则授权导演从要闻文本自由推断）。
- 事件地点只认正文真实提及的定居点，不会因玩家当前所在菜单而漂移。
- 每次生成（含【重新绘制】）都注入随机构图变体，重绘时导演被要求刻意切换景别/机位/瞬间——同一份周报每次出图不再雷同。
- 同时离屏渲染当事人的真实 3D 肖像与其家族/王国纹章（原版 BannerTableau 的完整旗面），一并作为参考图喂给视觉/生图模型。

### 4. 卡拉迪亚纪事画廊（大地图营地菜单）
- 点击大地图左下角菜单：`营地 (Camp) -> 卡拉迪亚纪事画廊 (AI 画卷)`。
- 可集中浏览当前存档已经生成的历史立绘与事件纪事插画，支持按条目查看提示词、复制、设为同分类默认图、删除到本地回收区以及打开缓存目录。

## 五、 提示词工作流与防偏色黑科技

### 1. 提示词导演的双引擎运作机制
```
[游戏事件/百科/对话触发]
       │
       ▼
[HeroVisualExtractor / EnvironmentVisualExtractor]
(提取文化传记、FaceGen骨相、HSV家族色、真实装备槽位、环境围城状态)
       │
       ├───────────────────────────────────────┐
       ▼ (开启多模态)                           ▼ (无多模态或离线)
[ScreenCaptureHelper]                [SynthesizeRuleBasedPrompt]
TableauView/ThumbnailCache 离屏渲染:  基于提取属性离线动态组装
人物3D肖像 + 家族纹章 + 现场实景      (含文化头饰/纹章铁律)
       │                                       │
       ▼ (核心修复)                             │
[SwapRedAndBlueInBitmap]                       │
DirectX BGRA -> 标准 RGBA 通道反转              │
       │                                       │
       ▼                                       │
[VisualDirectorEngine (LLM)]                   │
注入纯中文古典油画提示词准则                      │
输出纯中文高精度油画生图 Prompt                   │
       │                                       │
       └───────────────────┬───────────────────┘
                           ▼
              [UniversalOpenAiImageClient]
              调用兼容 API 生成古典写实油画
                           │
                           ▼
              [DiskImageCacheManager]
              本地持久化缓存 + Gauntlet 贴图展示
```

### 2. 独家防偏色机制细节
- **为什么以前黄色刺绣会变成蓝色？**
  DirectX 11 引擎的显存帧缓冲区以 BGRA 排列。红（R）与蓝（B）反转后，金黄色（高红高绿低蓝）直接被反转成青蓝色（高蓝高绿低红）。视觉大模型由于“看到的垫图就是蓝色的”，便会输出 `cobalt-blue trim`（深钴蓝滚边），生图模型便画成了蓝色。
- **本系统的解决方案**：
  1. 底层内存级遍历直接互换 R 与 B 字节（指针操作，极速且 0 内存开销）；
  2. 提取层引入 HSV 色相判定，明确把佩特罗斯家族等主辅色翻译为中文并打上铁律标签：
     `【极其关键颜色铁律：黄色/金色刺绣绝对严禁画成蓝色！严禁颠倒服饰颜色！】`

## 六、 常见问题与排错指南 (FAQ)

### Q1: 提示“生图失败：401 Unauthorized”或“404 Not Found”？
- **检查 API Key**：确认 MCM 中填入的 API Key 是否正确，首尾是否有误复制的空格。
- **检查 Base URL**：如果使用的是硅基流动，确保填写的是 `https://api.siliconflow.cn/v1`；不要遗漏最后的 `/v1`。

### Q2: 提示词是否支持查看和手动调试？
- 在百科、对话或周报弹出的立绘卡片上，点击 **【提示词】** 展开内容，再点击 **【复制】** 即可复制当前 Prompt；画廊详情区也提供 **【复制提示词】**。

### Q3: 为什么第一次生成时需要等待几秒钟？
- 系统包含两段异步请求：
  1. 视觉大模型理解角色 3D 垫图并扩写出中文生图提示词（约 1~2 秒）；
  2. 生图模型根据提示词进行扩散渲染出图（根据模型不同约 2~5 秒）。
- 网络与图像处理在后台执行；游戏对象读取和原生渲染准备由主线程处理。纹章仅在生成请求且缓存未命中时导出，同一时刻只运行一个离屏舞台；实际帧耗时仍需实机测量。已生成图片保存在本地缓存。

### Q4: 生成的图片保存在哪里？
- 保存在用户的本地文档目录下，并按当前存档隔离：
  `此电脑\文档\Mount and Blade II Bannerlord\AnimusForge\IllustratorCache\<存档标识>\<分类>\`
- 删除的条目会先移动到：
  `此电脑\文档\Mount and Blade II Bannerlord\AnimusForge\IllustratorCache\_trash\<存档标识>\`
- 每张 PNG 都有同名 JSON 元数据（主题、分类、提示词、默认状态和创建时间），不会跨存档命中旧图。

### Q5: 提示“生图失败：响应为空”或“生成请求超时”？
- **空回复**：已确认 2026-09-16 的两次失败返回 `content:null`、`completion_tokens:0`；仅凭此不能确认服务端内部原因。系统区分空响应、拒绝/过滤和无法提取图片，保留响应预览，不自动重试。解析器支持图片分块、字符串/对象形式的 `image_url` 以及后续有效候选。
- **参考图降级**：`images/edits` 仅在明确不支持接口时退回纯文本；空结果、鉴权失败、限流和服务端错误不再丢弃参考图重复请求。
- **纹章参考图**：已替换手工图集合成，改由原版 BannerTableau 渲染完整旗面，负责图案、配色、描边、旋转、镜像及多色背景；后台只归一化通道、缩放并编码无损 PNG。空白或无效导出省略参考图，当前保守检测也会省略刻意设计的纯色旗帜。双版本编译及模拟渲染结果的管线测试通过，真实游戏的导出颜色、方向、复杂旗面和最终模型遵循程度仍待验收。
- **现场环境**：有 Mission 时以实际实体/人物采样为依据，不混入酒馆等模板陈设；按引擎可见标志与玩家距离过滤，物体名称最多保留 20 个。没有玩家定位点时不把全场景当作附近。名称采样不等于视线遮挡判断或完整场景重建。
- **超时**：提示词导演请求限时 120 秒（携带多张参考图的多模态调用较慢）。真超时时卡片会显示"上游模型在限定时间内无响应"，稍后重试即可。
- 若长期稳定失败，请检查 Base URL / API Key / 模型名是否与服务商匹配（部分中转站仅支持特定模型或需要"使用完整调用 URL"）。

### Q6: 生成过程会在游戏里留下临时文件吗？
- 关闭自动清理时保留完整纹章导出 PNG 便于排查；不再产生新的 `banner_debug` 图集切片。历史调试文件保留，成功读取的立绘临时文件沿用自动释放行为。
- 如介意占用，在 MCM 中开启 **"生成完成后自动清理临时文件"** 即可每次生图后自动清理；画廊缓存与默认插图不受影响。
