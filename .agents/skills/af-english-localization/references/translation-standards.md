# 英化规范

从仓库根定位源文件与消费者。此文约束获准译文批次，不授权产品改动、全局安装或游戏覆盖。

## 文本分类与处置

| 文本 | 处置 |
| --- | --- |
| 菜单、MCM、提示、按钮、玩家通知、错误说明 | 英化展示层；核实是属性文字、TextObject、VM 字段还是 prefab 绑定 |
| 规则、前/主/后处理、记忆/外交/公报/生图提示词的自然语言 | 英化自然语言和语言要求；锁定协议格式、资格、动作和事实语义 |
| 中文比较、关键字、正则、字符、分隔与替换 | 追输入/输出和调用顺序；按实际契约适配英文，保留仍需兼容的中文/旧存档输入 |
| 技术键、枚举、类型、tag、参数名、日志结构、资源和绑定 ID | 保留；显示名字应与稳定标识分开，不因“看起来是中文”改协议 |
| 注释、未激活条件代码、次级加载资源、原始玩家自定义文字 | 单列审查，不冒充已显示的待译文本；不自动覆盖玩家内容 |
| 世界书正文 | 延期；目录与消费者见 Skill 的排除边界，原文件/哈希保持 |

分类器只是提示。字符串在 `string.Format` 内也可能最终进入日志；JSON value 也可能是枚举、选择器或匹配条件。必须看外层调用与消费者，不只看 token 类型。

## 英语表达

- 优先核对当前原版英语语言资源中的人物/文化/地名及既有 AF 英语用语；没有证据就登记待定，不编造“官方译名”。同一术语同一业务义保持一致，不强求不同上下文共享一个译文。
- 按本批实际用语维护少量术语决策和来源。按钮用简洁动作词；提示描述状态和可执行操作；MCM 说明保留单位、范围、默认/重启含义，不改参数默认值来“适应英语”。
- 不改语气、阵营关系、许可、数值、触发资格、时间/概率或失败条件。强制与建议（must/may）、否定、条件和例外不能弱化、扩大或漏译。
- 有计数、姓名和动态内容时考虑英语单复数、语序、称谓；保留数据来源与 formatter，不让展示字符串参与身份匹配。
- 沿用模块的字体、大小写和排版风格；不以固定扩宽/缩字、硬编码截断或加省略号掩盖缺字/未加载资源。真实面板长文本需人工验收。

## 占位符、格式与编码

- 对照原始 raw 字串及真实调用：TextObject 的 `{=ID}`/变量、`.NET` 数字格式与索引、插值表达式/格式、转义括号、换行与富文本控制符都保留语义。英语重排允许改变顺序，但不能丢失变量、改变类型或数量。
- 提取器 `placeholders` 字段是线索，不是穷尽解析；复杂插值/嵌套变量以当前源与 formatter 为准。不可只用正则计数声称协议一致。
- 不把翻译后的展示文案作为存档键、资源 ID、JSON 属性、tag 或比较值。`text_id`/occurrence ID 只属于盘点证据；不得据此自动生成需要稳定的运行时身份。
- 新增文本按仓库约定保存 UTF-8/行尾，保留 BOM/声明等必要契约。Json.NET 风格预设可能有字面控制符；按实际消费者检查，不顺手批量清洗既有正文或只用严格 JSON 解析器的失败判运行失败。

## 实际加载和回退

- 复用既有 TextObject、语言 XML 或模块文本 catalog；读真实 loader/fallback 顺序、英文 `language_data.xml`、`content/content-map.json` 和相关 EmbeddedResource。英文源文件存在但没有引用/加载不算英化。
- 只加当前调用确需的资源/适配，避免新建全局语言服务或复制中文/英文两套业务实现。修改语言资源前确认英语默认、中文覆盖和缺 ID 回退的实际行为，不强改游戏语言设置。
- 路径/文件后缀变化涉及映射、嵌入名、loader 和兼容旧配置，必须同批接通；纯翻译不得擅自更名模块、程序集、Bootstrap 或输出目录。
- 保留用户自定义内容的优先级；默认英语资源不授权重置已有提示词、玩家预设或导入数据。

## 提示词与语言依赖

- 搜索本批中文专用约束：必须中文、中文标点/段落标签、输出字段值、词数/字符数及示例。改自然语言时核对前处理 → 主链路 → 后处理和真实解析器，示例/输出语言与协议一致。
- 信使、自由对话、场景喊话使用同类规则和同一历史/事实语义。自然语言翻译不能改变话题资格、tag 注入、动作授权、目标验证、执行顺序或 AFEF 已发生事实定义。
- 中文关键词并非都应删除；结合输入来源决定替换、补充或冻结。新增英文必须有真实入口和消费者，不留下没人读取的词典或 fallback-only 分支。
- 原版动态名字、用户原文和延期世界书仍可能包含中文；分别说明来源，不能为“零汉字”删除资料或强制转写所有名字。
- 调整语音/模型语言前确认当前 provider 的能力及使用边界；英化不授权下载模型、切换服务或发起付费调用。

## 源码归属与同步

保持双 API、一个 AnimusForge 模块和既有 Bootstrap；热点不新增反射/全量扫描。可复用 GCCZ 文案/规则留在其独立代码区，AF 文件只做必要的薄接线。

触及 GCCZ 可复用规则或集成契约时遵守现有双边表示/同步要求，但不得越过工作区授权直接写其他树。未获对应路径许可时，只在当前工作区形成明确标注“待同步”的独立补丁/说明，不能报告双边已完成。Skill 文档本身不触发产品同步。
