# 英化审查与验收

审查限于当前批次、实际消费者和受影响的相邻回归。用户只要求审查时只读；实现阶段则在交付前执行下面的检查。结构 lint/字符串匹配只是辅助证据，不是译文或游戏验收。

## 先明确审查对象

记录目标 revision/差异、功能/渠道、源记录是否仍适用，以及当前要求的是 Skill、盘点、译文实现还是发布。原清单的行列、自动分类、旧构建报告都不能代替当前源码/资源证据；仅文档提交不要求重跑无关游戏构建。

## 工程师自审

- **范围**：延期世界书原文件未改、正文未流入新译文/fixtures；不因文件夹叫 `PlayerExports` 就全跳过公开非知识资源。不读取/推送私人导出、凭据或本地专用历史。
- **语义**：原文与译文的条件、否定、许可、例外、默认值、数字/单位和动作强度相同；每个实际使用位置都已确认，不能按去重键一键覆盖。
- **契约**：逐项确认冻结标识、变量、插值/数字格式、tag 语法与 JSON schema；展示值没有意外进入比较、存档或路由。语言依赖逻辑须覆盖相关旧中文输入、新英文输入及最关键反例。
- **加载**：loader → 语言配置/映射/嵌入 → VM/MCM/prefab 或 prompt 注入 → 实际消费者。核对缺失 ID、回退、用户内容优先级；孤立英文资源或未消费的适配不算完成。
- **渠道**：提示词资格、主链路语言、后处理解析和执行标签、history/AFEF 含义一致；只改一个渠道时说明相邻渠道为何不受影响，否则定向核对三渠道。
- **干净改动**：无弃用 helper、复制业务实现、失效 bridge、未用词典/开关或冲突。只删除确定由本批替换掉的路径；需要保留的兼容用途给实际调用/旧数据依据。
- **版本**：保持双 API 和单模块身份。受影响 C#、API 或嵌入/加载配置按现有官方流程做必要双版本/Bootstrap 验证，不改一键覆盖入口来让测试通过。

优先复用直接验证真实生产代码的专项。源字符串存在、模拟投影、C# parser 通过、扫描器全绿或过去另一 revision 的构建都不能代替当前链路证据。相关输入未变且环境/参数相同的有效结果可复用。

## 英语玩家视角

按实际入口验证一个主流程和最相关的失败/回退流程：

1. 以英语游戏语言打开对应菜单/MCM/面板：文字真实加载，按钮语义明确，变量不裸露、无截断/溢出或焦点输入退化。
2. 核对动态数量/人名、空数据、长文案及当前功能最相关的失败反馈。需要旧中文数据时确认仍可读，不以重置存档/配置制造“通过”。
3. 涉及 LLM 时核对实际请求的英语约束、响应、tag 清理/解析、动作与事实结果；没有真实 provider 权限/环境时，只记录离线 replay/源码推演，不能称实机输出通过。
4. 将延期世界书、原版动态名字和用户原文与已英化展示层的意外中文回退区分。未授权的 OCR/图片重绘、模型下载、付费调用或游戏覆盖不作为审查的隐含动作。

不能实机时给出上述适用项目的简短人工步骤和缺口；可将已验证部分交付为“离线通过，实机待验”，但不得称全英文发布已验收。两种视角由同一代理完成就如实标注自审，不虚称独立评审或两个专家。

## 问题分级与退出

- **阻断本批标为完成**：世界书正文越界、契约/占位符破坏、语义变化、实际资源/消费者没接通、英语或既有输入发生相关回归、伪报未执行验证。缩小/修复受影响范围，不让无关批次被历史 HOLD 无限阻塞。
- **必需证据缺口**：本批必要构建/加载/解析验证缺失，不能称对应条件已通过；完成独立可验证部分并说明精确阻碍。若用户明确只接收带限制的源码交付，仍保留限制，不把条件自动改成通过。
- **可后续项目**：不影响契约的风格建议、已明确延期的世界书/视觉资产、未授权的实机/付费测试；登记用途和风险，不静默扩大任务。

确证问题要有文件/行号、输入/配置、原文/译文或实际效果和最短复现；推测/建议单列。默认两种视角各做一次；发现本批缺陷后定向修复并重验失效证据，必要门槛满足即退出，不滚动追加全仓审计。

## 按变更选择验证

| 本批变更 | 最小有效证据 |
| --- | --- |
| Skill/文档 | frontmatter/YAML、引用和路由、授权/边界自审、`git diff --check`；不冒充功能验证 |
| 提取器 | 原始值/转义/条件代码/重复引用/延期排除的行为检查、可复现源哈希；计数不证明运行可达 |
| XML/JSON 文案或提示词 | 实际消费者的解析、加载/嵌入/映射、占位符和冻结标识、相关渠道/回退；必要游戏/LLM项目另列 |
| C# 文案/匹配/语言适配 | 最小相关行为测试、必要双 API/Bootstrap 构建、旧/新输入及相邻回归；构建不等于实机 |
| 打包/部署/发布 | 单独授权后才执行原官方流程，确认实际产物、玩家数据保护与回滚；未经实机不称全部验收 |

## 提交、推送与报告

源提交只包括本批获准文件。记录清理了什么、有效检查、未执行项和有意保留中文的原因；原始盘点与翻译跟踪不混写，不夸大覆盖率。

当前用户明确要求推送时，核实目标仓库/分支、远端起点、本地 tree/提交及最终远端 SHA；不改 main、不 force-push。远端有别人更新或认证/网络失败就保留本地成果、检查实际状态后处理，不用覆盖或“已推送”掩盖失败。不要把本机私有恢复脚本写成别的宿主必须存在的 hooks；可用常规 Git 或当前环境合法且能验证的等价工具。
